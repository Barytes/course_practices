第 2 章 · 词、编号与分词器

模型不认识汉字，只认识整数。分词器是词典加切分规则：把文本切成词元，再换成编号；生成结束后再把编号拼回文本。

为什么不能一个汉字一个编号

如果每个汉字、每个英文单词、每个标点都占一个独立编号，词表会非常大。词表一大，嵌入层和输出层的参数就会爆炸。MiniMind 这类小模型尤其吃不消：词表若有 15 万，光嵌入层就是 150000 × 768 ≈ 1.15 亿参数，已经比整个 MiniMind-3 还大。

反过来，如果按字节切（每个字节 0–255），词表极小，但「中华人民共和国」这种常见短语会被拆得粉碎，模型要用很多层才能把它们重新拼成概念。折中方案是 BPE（Byte Pair Encoding，字节对编码）：从字节出发，反复把最常见的相邻片段合并成一个新词元，直到词表达到预定大小。

MiniMind 的词表为什么是 6400

Qwen2 一类中文友好模型的词表常在 15 万左右，同样一段中文会被切成更少的词元，生成也更省步数。MiniMind 故意只用 6400。代价是中文压缩比大约 1.5–1.7 个字符 / 词元，弱于大词表；收益是嵌入层只有 6400 × 768 ≈ 491 万参数。对 64M 的模型，这个比例是健康的。

官方脚本 trainer/train_tokenizer.py 展示了如何用 tokenizers 库训练：预分词是 ByteLevel，模型是 BPE，词表大小 6400，并预留一批特殊标记。教材要求你直接加载官方已经训好的分词器，不要自己重新训——否则你训出来的模型无法和社区权重互换。

特殊标记不是普通词

对话、思考、工具调用都靠特殊标记把结构告诉模型。MiniMind-3 主线与 Qwen 风格的对话模板对齐，常见几个：

标记角色
<|im_start|> / <|im_end|>一段角色发言的开始与结束。配置里分别作为 bos 与 eos。
<|endoftext|>填充（padding）和未知回退，也常当作 pad / unk。
<think> / </think>显式思考块。推理时用 open_thinking 决定要不要先写出思考开头。
<tool_call> / <tool_response>工具调用与工具返回。

预训练阶段几乎用不到对话模板：每条样本是一段纯文本，左右加上开始/结束编号即可。监督微调才会把 user / assistant / system / tool 展开成带这些标记的字符串。第 15 章会写这一步。

一个可以手算的小分词器

在接官方 BPE 之前，先用「字符级词典」建立 encode / decode 的肌肉记忆。这和你目录里的 attention.py 草稿是同一思路：特殊符号放最前面，保证编号稳定。

注意：你原来的草稿里方法名是 endcode，应写成 encode。另外 set[str]("".join(corpus)) 这种写法不是「把字符串变成字符集合」的正确方式，应直接 set("".join(corpus))。

压缩率怎么读

「100 个中文字符 ≈ 67 个词元」只是粗算。英文压缩比更高（约 4–5 字符 / 词元）。训练参数 max_seq_len 指的是词元个数，不是字符数。样本短于它会被填充浪费计算，长于它会被截断丢掉语义。这是第 14 章选截断长度时要权衡的事。
