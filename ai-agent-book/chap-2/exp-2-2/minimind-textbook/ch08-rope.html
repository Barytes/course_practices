第 8 章 · 旋转位置编码

到目前为止，注意力把序列当成「一组无序卡片」——打乱词序，分数几乎不变。旋转位置编码把位置写进查询和键的几何里，让点积自动带上相对距离。

没有位置信息会怎样

「狗咬人」和「人咬狗」若只是同一袋词元，自注意力无法区分。早期做法是在嵌入上加一份绝对位置向量。更好的做法是：不往输入上加东西，而是在算注意力之前旋转 Q 和 K，使得

(Rm q) · (Rn k) = q · (Rn−m k)
位置 m 的查询与位置 n 的键的点积，只依赖于相对距离 n−m，以及 q、k 本身。

这就是旋转位置编码（Rotary Position Embedding，RoPE）。MiniMind-3 和 Qwen3 都用它。

二维旋转，推广到 96 维

平面上把向量旋转角度 θ，可以用一个 2×2 矩阵。RoPE 把 head_dim 维两两一组，每一对用不同的频率旋转。第 i 对的频率是

ωi = θbase−2i / head_dim　　i = 0, 1, …, head_dim/2 − 1
MiniMind-3 的 θ_base 即 rope_theta = 1e6。较大的基频让高频（近距离）和低频（远距离）分得更开，有利于长上下文。

位置 m 上，第 i 对被旋转 m · ωi。低频那几对转得很慢，即使 m 很大，两个位置的相对角也还能分辨；高频转得快，负责近距离的精细差别。

官方用「一半对一半」而不是交错偶数奇数

旋转的实现有两种常见布局：

  • 交错：维度 0 和 1 一对、2 和 3 一对……
  • 对半：前一半维度和后一半维度配对，即 (-x[..., d/2:], x[..., :d/2])

MiniMind 用第二种，与许多 Hugging Face 实现一致。先预计算每个位置的 cos、sin（每个都是 head_dim 长，因为把半长的频率表复制了一份拼到 96 维），再：

这就是复数乘法 (q_cos + i q_sin) * (cos + i sin) 在实数张量上的写法。V 不旋转：值是「内容」，位置只应影响「能不能匹配」，不应扭曲被提取的内容本身。

预计算一张很长的 cos / sin 表

训练和推理时位置是 0, 1, 2, … 的整数，没有必要每次现算。官方在模型初始化时算到 max_position_embeddings=32768，存成 buffer（不进优化器，也不进检查点）。

如果生成第 21 个词（下标从 0 计的位置 20）时仍用位置 0 的 cos/sin，相对距离就全错了。键值缓存和位置编码必须共用同一套 start_pos。

旋转插在哪一步

正确顺序是：

  1. 线性投影，reshape 成 [B, T, 头数, 96]。
  2. 查询/键归一化（下一章）。
  3. 旋转 Q 和 K。此时还是「头维在后」的布局，unsqueeze_dim=1 会把 cos 插到头维上广播。
  4. 拼接键值缓存。
  5. repeat_kv，再 transpose 去算分数。

先旋转再拼接：新词用新位置的 cos/sin，旧键在缓存里已经带着旧位置的旋转，不能再转一次。

YaRN：推理时把位置「拧松」

模型若在长度 2048 上训练，直接推理 8192 会让旋转角度跑出训练分布。YaRN 把一部分频率按比例压低，等效于把长序列的位置映射回较短的区间，并给注意力分数乘一个补偿因子。MiniMind 在 inference_rope_scaling=True 时启用：

字段默认含义
typeyarn使用 YaRN 而不是线性插值。
factor16目标长度大约是原长度的 16 倍。
original_max_position_embeddings2048训练时认定的原长度。
beta_fast / beta_slow32 / 1高频与低频的分界，中间用斜坡混合。
attention_factor1.0乘在 cos/sin 上的注意力补偿。

教学实现可以先不管 YaRN：rope_scaling=None 时 precompute_freqs_cis 就是上面那几行。需要外推时，把官方函数里 if rope_scaling is not None 那一段原样拷入即可。官方还用 end / orig_max > 1.0 判断是否真的在做外推。

现在动手写：接到注意力上

position_embeddings 不要在注意力内部用 torch.arange(seq_len) 现造——那会在有缓存时永远从 0 开始。让外层 MiniMindModel 算好 start_pos，把切片后的 cos/sin 传进来。

频率表的 dim 是头维度

写 precompute_freqs_cis(dim=config.hidden_size) 是错的。必须是 config.head_dim。传 768 时，你会在 96 维的 Q 上广播失败或静默算错。
