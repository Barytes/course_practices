第 13 章 · 拼装 MiniMind-3-MoE

注意力一行都不用改。把每一层的前馈换成「先由路由器选专家、再只跑被选中的 SwiGLU」，就得到 MiniMind-3-MoE。

这一章只要记住

前馈复制成 4 个专家。每个词只去分数最高的那 1 个，输出还要乘回门概率。另外加一项很小的辅助损失，防止所有词都挤进同一个专家。

混合专家要解决什么

稠密前馈对每个词都跑同一套 5.6M 参数。若想增加记忆容量，最笨的办法是把中间维加宽，于是每个词的计算也变贵。混合专家把前馈复制成 N 份，每个词只激活其中 K 份。

生活比喻

医院有 4 个专科，分诊台（路由器）看一眼把你送到其中 1 科。医院总编制变大，但你这次只占用 1 个诊室。没有「所有人都要先去的那个公共诊室」——MiniMind 去掉了共享专家。

项取值
专家个数4
每个词选几个1（top-1）
共享专家无
总参数 / 激活参数约 198M / 64M
p = softmax(x Wgate)　　选 k* = argmax p　　输出 = pk* · Expertk*(x)
乘回 p_k* 很重要：否则路由器的分数无法通过专家输出反传，门就学不到东西。

按专家分桶，而不是 for 每个词

把 [B, T, 768] 摊成 [B·T, 768]，算出每个词的 topk 下标，然后对专家 i：找出选了 i 的那些行 → 只把这些行送进 experts[i] → 乘上门概率 → 用 index_add_ 写回原位置。

训练时若某个专家整批都没被选中，官方加一个恒为 0 的假梯度，让这些参数仍出现在计算图里。推理时不要走这分支。

负载均衡辅助损失

若放任不管，路由器很容易把所有词都塞给同一个专家。辅助损失鼓励「每个专家被选中的频率」与「门给出的平均概率」相匹配。训练总损失是 交叉熵 + 各层 aux_loss 之和。推理时 aux 置零。

代码怎么对上原理

  • self.gate 是 [768, 4] → 分诊台给 4 个专科打分。
  • experts 里每个都是第 10 章的 FeedForward → 专科诊室就是一套 SwiGLU。
  • topk(..., k=1) → 每个词只去 1 个专家。
  • expert(...) * weight → 乘回门概率 p_k*，路由器才能学。
  • index_add_ → 按专家分桶写回原位置，不要对每个词写 Python for。
  • 0 * sum(p.sum()...) → 没被叫到的专家仍挂在计算图上，数值不变。
  • aux_loss 存在模块上，第 12 章的 Model 会把各层加起来。

不要自己加 shared_experts，否则权重对不上，激活参数也不再是 64M。

自测

  • top-1 时 norm_topk_prob 实际上会做什么？
  • 辅助损失为什么要乘专家数 N？
  • 推理时 model.eval() 后 aux_loss 为什么必须是 0 张量而不是 Python 的 0？
自测答案（先自己想）
  1. top-1 时只选中一个数，除以自己还是自己。这行几乎没效果，但 top-2 时会把两个概率重新归一化。保留它是为了和配置开关一致。
  2. f 和 P 都是大约 1/N 量级，点乘再求和大约是 1/N。乘 N 后尺度不随专家数漂移，4 专家和 64 专家的系数才可比。
  3. 训练循环写成 loss + aux_loss。Python 的 0 和张量相加可能得到错误类型或离开计算图。0 张量能安全相加。
