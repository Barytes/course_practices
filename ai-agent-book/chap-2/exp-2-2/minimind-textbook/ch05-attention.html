第二部 · 积木

第 5 章 · 注意力：查询、键、值

这一章只做一件事：让每个位置用「问题」去检索其他位置的「索引」，再按相似度把「内容」加权求和。先不要位置编码，不要多头，不要缓存。

这一章只要记住

每个词变出三份信息：查询 Q（我在找什么）、键 K（我这份内容的标签）、值 V（真正要提供的内容）。用 Q 去点积所有 K，得到分数；softmax 成权重；再用权重去混合所有 V。

没有注意力会怎样

如果每个词只经过自己的线性层，位置 5 永远无法直接读到位置 1 写过的信息。卷积能看窗口，循环能看历史，但窗口和逐步传递都有上限。注意力让任意两个位置之间有一条直接通路：分数由数据决定，不由距离硬编码。

检索比喻，请把它当成真的

生活比喻

图书馆里每本书有三样东西：你手里的问题条（Q）、书脊上的分类号（K）、书里的正文（V）。你拿问题条去和每本书的分类号比对，越像的书，你从正文里摘得越多。自注意力的特殊之处：Q、K、V 都来自同一串输入，只是乘了三块不同的权重。所以叫「自」。

  • 查询 Q（Query）：我现在在找什么？
  • 键 K（Key）：我这份内容的索引词是什么，供别人检索？
  • 值 V（Value）：我真正要提供的内容是什么？

位置 i 拿自己的查询，去和所有位置的键做点积，得到一组分数；分数越大，说明「我要的」和「你的索引」越匹配。把分数做成权重，对所有位置的值加权求和，就是位置 i 读到的上下文。

用 3 个词手算一遍

假设每个词暂时只用 2 个数，序列是三个位置，已经得到：

分数矩阵是 Q 乘 K 的转置。Sij 表示「位置 i 的查询 · 位置 j 的键」：

S = Q KT　　形状 [T, T]

位置 0 的查询是 [1, 0]，和三本「书脊」点积得到第 0 行：[1, 0, 1]。它更关注位置 0 和 2。

还不能直接拿 S 去乘 V，因为点积的尺度会随维度变大。标准做法是除以 √d，d 是每个头的维度：

Attention(Q, K, V) = softmax(Q KT / √d) V
softmax 沿「键」这一维做，即每一行变成一组和为 1 的权重。

这里 d=2，√d≈1.414。位置 0 的缩放分数 ≈ [0.707, 0, 0.707]。softmax 之后大约是 [0.40, 0.20, 0.40]。再去混合 V：

0.40×[10,0] + 0.20×[0,20] + 0.40×[30,0] ≈ [16.0, 4.0]

人话：位置 0 大约四成抄位置 0 的内容、两成抄位置 1、四成抄位置 2。

除以 √d 的原因：若 Q、K 各维独立、方差约为 1，则点积的方差约为 d，标准差约为 √d。除掉之后，softmax 的输入不会随维度爆炸，权重才不会变成「几乎只认一个位置」。

张量形状（先单头）

张量形状怎么念
x[B, T, D]B 句话，每句 T 个词，每个词 D 个数。MiniMind 的 D=768。
Q / K / V[B, T, D]x 乘三块线性层。单头时先令头维度等于 D。
分数[B, T, T]每个查询位置对每个键位置打一个分。
输出[B, T, D]权重乘 V，再经输出投影。

对应原理图书馆三件套 + 公式 softmax(QKᵀ/√d)V。下面「代码怎么对上原理」逐行翻译。

代码怎么对上原理

  • q_proj(x) → 把每个词变成「我在找什么」（问题条 Q）。
  • k_proj(x) → 把每个词变成「书脊分类号」（键 K）。
  • v_proj(x) → 把每个词变成「正文」（值 V）。三块表不同，所以叫「自」注意力。
  • k.transpose(-2, -1) → 让「查询位置 × 键位置」能做点积，得到 [T, T] 分数表。
  • * scale 且 scale = 1/√d → 公式里的 /√d，防止分数随维度爆炸。
  • softmax(..., dim=-1) → 每一行变成加起来为 1 的权重。dim=-1 是「对着所有键」。
  • weights @ v → 用权重去混合正文，得到每个位置读到的上下文。
  • o_proj → 读完再做一次线性混合。单头时看起来多余，第 7 章多头拼回去时它就会派上用场。

现在这个实现有一个故意的缺陷

位置 0 的查询已经能看到位置 4 的键和值。训练语言模型时这等于作弊：预测「下一个词」时偷看了未来。第 6 章会用上三角为负无穷的掩码禁止这件事。先保留这个缺陷，是为了让你看清掩码到底盖住了矩阵的哪一块。

softmax 之前为什么先转 float

半精度（float16 / bfloat16）的动态范围有限。分数里若出现较大的数，softmax 的 exp 可能溢出成 inf。官方在手工注意力路径上写的是 F.softmax(scores.float(), dim=-1).type_as(xq)：用 float32 算权重，再转回原来的精度去乘 V。教学代码请保持这一习惯。

草稿 attention.py 里如果已经有 Attention.forward，对照上面清单检查三件事：有没有除以 √d、softmax 是不是沿最后一维、输出形状是不是和输入一样。不必删掉你的 CharTokenizer，那是第 2 章的热身。

常见卡住

  • 分数形状不是 [B, T, T]。——k.transpose 转错维了。应转最后两维，让「序列」和「序列」对齐。
  • 权重某一行加起来不是 1。——softmax 的 dim 写错了，写成对批次或对隐藏维了。
  • 把 Q 和 V 点积。——检索必须是 Q 对 K；V 只在有了权重之后才出场。

自测

  • 若交换 Q 和 K 的角色，分数矩阵发生什么？输出还是「按内容加权」吗？
  • 为什么除的是 √d 而不是 d？d 很大时，不除会导致 softmax 怎样？
  • 画出 T=4 时分数矩阵的 4×4 格子。下一章要盖住的是严格上三角，还是包含对角线？
自测答案（先自己想）
  1. 分数矩阵会变成原来的转置：变成「键去检索查询」。再用这组分数去混合 V，语义就拧了——索引和问题对调，加权不再表示「我要的内容」。
  2. 点积的标准差大约是 √d，不是 d。不除的话分数极大，softmax 几乎变成 one-hot：每个位置只看一个人，注意力失效。
  3. 下一章盖住严格上三角（不含对角线）。对角线是「看见自己」，允许；右上角是未来，禁止。
