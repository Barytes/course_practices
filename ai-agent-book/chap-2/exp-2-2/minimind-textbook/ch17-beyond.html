第四部 · 训练

第 17 章 · LoRA、偏好优化与强化学习

MiniMind-3 和 MiniMind-3-MoE 的主体到第 16 章已经闭环。后训练不改结构，只改「更新哪些参数、用什么信号」。本章把官方从零实现的几条路讲清楚，作为继续往下读源码的地图。

先分清三条动机

动机方法你改的是什么
便宜地适应一个领域，尽量别忘通用能力LoRA在原权重旁加低秩增量，只训练增量
更喜欢某种回答、不喜欢另一种DPO（RLHF 的一种）用现成的「更好/更差」对，直接推策略
让模型在可自动打分的任务上试错变强PPO / GRPO / CISPO / Agent在线采样，用奖励更新策略

这些都不需要再写一套 Transformer。它们调用的仍是你第 12、13 章的 forward。

LoRA：把 ΔW 分解成两个瘦矩阵

全参数微调更新整个 W。LoRA 冻结 W，学习

W'x = Wx + B(Ax)　　A ∈ Rr×d，B ∈ Rd×r，r ≪ d
A 用高斯初始化，B 用全 0，于是训练第一步 ΔW=0，模型行为与基座相同。

官方 model_lora.py 只给方阵线性层挂 LoRA（in_features == out_features），MiniMind-3 里主要是 768×768 的 q_proj、o_proj 等。非方阵的 k_proj（768→384）默认不挂。前向被替换成「原线性 + lora」：

训练结束后可以把 W ← W + B A 合并回去，推理不再需要 LoRA 模块。身份数据、医疗数据这类小 jsonl 就是为这条路径准备的。

策略优化的统一视角

后面几个算法名字很吵，其实都在优化：

J = E[ Φ(rt, At) − h(KLt) ]
r_t 是新策略与旧策略在该词元上的概率比；A_t 是「这个动作比基线好多少」；KL 防止跑去很远的奇怪策略。

差别只在 Φ、A、h 怎么定义。

DPO：离线的「更好 vs 更差」

数据里每条有 chosen 和 rejected 两段回复。不训练奖励模型。损失鼓励：相对参考模型，chosen 的对数概率要比 rejected 更高，高出的程度由 β 控制。实现上要跑当前策略和冻结的参考模型（通常是 SFT 权重）各一遍。显存比 PPO 小，但不能在线探索，对「会不会做对题」帮助有限。

PPO：在线，带一个价值网络

用当前策略采样回答，奖励模型（或规则）打分，价值网络估计「这句大概值多少分」，二者之差是优势 A。概率比被 clip 在 1±ε 里，防止一步更新过大。要同时维护 Actor 与 Critic，MiniMind 上收敛偏慢、显存偏高，但它是理解后续变体的基准。

GRPO：用一组回答代替价值网络

同一道题生成 N 个回答，用组内平均分当基线，标准化得到 A。不再需要 Critic。若 N 个回答分数几乎一样（退化组），梯度接近 0。小模型上这个问题很严重，所以题目难度必须落在模型刚能够到的区间。DeepSeek 之后大量 xxPO 都以它为共同祖先。

CISPO：被 clip 之后梯度别断

PPO/GRPO 把 r_t clip 成常数后，那一段对策略参数的梯度会断掉。CISPO 把 r_t 只当作截断后的权重，去乘 log π，梯度仍能流回。官方把它做成 train_grpo.py 的 loss_type='cispo'，不必另起一套脚本。

Agentic RL：多轮工具，延迟给分

train_agent.py 优化的不是单句回答，而是一条轨迹：模型可能多次发出 tool_call，环境执行后把 observation 拼回上下文，直到结束才算总分（答案对不对、工具合不合法、格式、是否没完成……）。这是稀疏、延迟的奖励。rollout 还可以交给独立推理引擎，训练侧只负责更新——官方称之为训推分离的最小版本。

小模型上的奖励稀疏

若用「数学题对错」这种 0/1 奖励去训 64M 模型，几乎所有采样都是 0 分，优势全是 0，策略不更新。官方演示更常用 InternLM2-1.8B-Reward 这类给出连续分数的奖励模型，让「很差」和「稍好一点」仍能分开。规则奖励可以混进去，但不要在超纲题上只给二元分。

建议你怎么往下读源码

  1. 先把第 12、13 章的模型与第 16 章的 generate 写对，这是所有后训练的公共底座。
  2. 读 model/model_lora.py + trainer/train_lora.py，这是最短的后训练闭环。
  3. 读 DPODataset 与 train_dpo.py，弄清 chosen/rejected 的 mask 如何只盖助手段。
  4. 带着「Φ、A、h」三件套去读 train_ppo.py / train_grpo.py，不要被类名吓住。
  5. 最后读 train_agent.py 与 rollout_engine.py，看多轮拼接和延迟奖励。

后训练会收「对齐税」

官方评测里，Agent 权重在工具题上明显强于 full_sft，但开放问答更容易胡编。这不是 MiniMind 独有：优化目标变窄后，模型会更会迎合当前奖励。选择权重时按任务：要工具就用 agent，要闲聊稳健就用 full_sft。
