这一章只要记住

按顺序读；每章先搞懂「它在整台机器的哪一格」；看到 [B, T, 768] 就念「几句话、每句几个词、每个词 768 个数」。形状对了，再谈数字对不对。

这本书的推进方式

语言模型看起来很大，其实是同一件小事重复很多遍：根据已经出现的词，预测下一个词。

MiniMind-3 把这件事拆成大约十个可以单独理解的零件。本书按这个顺序一次只加一个零件：

  1. 先用人话和比喻建立直觉。
  2. 再用 2～4 个词、2～4 个数字这种超小例子手算。
  3. 然后写几行 Python，用断言检查形状。
  4. 最后才对照官方源码：「他们把这三行合成了一行」。

因此请按章节顺序读。第 5 章的注意力还不包含位置编码，不是作者忘了，而是故意的：先把「用问题去检索索引、再按分数提取内容」写对，再给它加上位置。一上来把旋转、分组、缓存缠在一起，几乎一定晕。

生活比喻

像学开车。第 5 章是「方向盘怎么打」；第 6 章才是「后视镜和倒车雷达」；第 8 章才是「导航告诉你现在在第几米」。不要指望第一节课就把自动泊车学会。

你需要准备什么

  • Python 3.10 左右，以及 PyTorch。有 NVIDIA 显卡最好；没有也没关系——用 CPU 跑「形状检查」和「三五个词的前向」完全够用。
  • 会写函数、for 循环、list / dict。矩阵乘法不要求手推公式，但要能接受「一排数字乘一张表，得到另一排数字」。
  • 能打开官方仓库：jingyaogong/minimind。本教材不会要求你把整个仓库抄进作业目录。
  • minimind_dataset/ 是数据下载位置，仓库里只保留空目录。完整训练数据在 GPU 机器上按 MiniMind 官方说明下载；第 14 章会告诉你最小可跑的数据长什么样。

「从零实现」指什么，不指什么

从零的意思是：模型结构、注意力、键值缓存、混合专家怎么选、损失函数、生成循环，都用 PyTorch 自己写。不调用 transformers.LlamaModel 这种已经封装好的大模型类。

不是从零的部分：矩阵乘法、反向传播（自动根据对错改参数）、AdamW 优化器，仍然用 PyTorch 提供的。重新发明这些对理解 MiniMind 没有帮助。

分词器官方已经训练好了。第 2.5 章会用 minbpe 把切词算法亲手写一遍，但不要用自己的词表去训练 MiniMind-3——词表一变，权重、数据、社区模型全都对不上。就像换了一本词典，旧书页码全失效。

必须先会的三件事：形状、线性层、softmax

后面每一章都建立在这三件事上。现在用超小数字讲清楚，后面就不用每次重新解释。

1. 形状怎么读

张量 = 按格子排好的一堆数字。中括号里的列表叫形状。

一维 [3]三个数排成一行
[1.0, 0.5, 2.0]
二维 [2, 3]2 行 3 列的表
像 Excel 小表
三维 [2, 5, 4]2 张 5×4 的表
两句话，各 5 个词，每词 4 个数

本书默认：

  • B = batch = 一次处理几句话
  • T = 一句话有几个词元
  • D = 每个词元用几个数字表示（MiniMind-3 是 768）

所以 x.shape == [2, 5, 768] 永远念作：2 句话，每句 5 个词，每个词 768 个数。卡住时先把形状念出来，再看代码。

形状里的最后一个数字，常常是「每个词自己的那一串」。归一化、线性层，多半都作用在这最后一维上，句子长度 T 不会变。

2. nn.Linear 在干什么

nn.Linear(3, 2) 的意思：每个位置原来有 3 个数，乘一张可学习的表，变成 2 个数。

对一整句话，线性层会对每个词各自做一次同样的乘法。所以输入 [B, T, 3]，输出 [B, T, 2]，词的个数 T 不变。这就是为什么可以放心说「句子长度在这一步不会变」。

MiniMind 里绝大多数线性层没有偏置（bias=False）：只乘表，不再额外加一个常数向量。这是为了和 Qwen3 的权重对得上，不是因为偏置「不好」。

3. softmax 在干什么

输入一串分数，输出一串大于 0、加起来等于 1的权重。

有两个重要推论：

  • 若某个格子是负无穷，e^(-∞)=0，权重就是真的 0。因果掩码靠的就是这一招。
  • 若分数差得特别大，softmax 会几乎变成「只认最大的那个」（几乎 one-hot）。所以注意力里要把点积除以 √d，避免分数爆炸。

每一章你要做什么

  1. 读懂这一步在整个前向计算里的位置。每章开头都有黑底框：「这一章只要记住」。没有它，模型会怎样，下一节会说。
  2. 看一个小数字例子。3 个 token、2 维向量这种规模，是为了让你能用计算器算，不是为了展示性能。
  3. 按「现在动手写」里的代码，自己敲一遍。建议放到 exp-2-2/ 下一个你自己的 minimind3/ 包里，章与章之间追加，不要每章新建互不相通的文件。
  4. 跑形状断言。如果张量形状对不上，后面所有章节都会错。形状对了，再谈数值对不对。
  5. 对照官方。官方把很多行压得很紧。教材会拆开写，并指出「官方把这三行合成了一行」。
  6. 做自测，再展开答案核对。先自己说人话，不要立刻点开。

代码写到哪

不要每章新建一个互不相通的脚本。正式实现全部写进 exp-2-2/minimind3/ 这个包，文件已经建好。完整对照表见 动手地图。

读公式时怎么不晕

本书公式很少，出现时都带一句「读作……」。规则：

  • 先读文字，再看公式。公式只是把刚才那句话缩写成一行。
  • 下标 t 几乎总是「第几个词」。xt = 第 t 个词元。
  • 竖着的一小撮叫条件：P(下一个词 | 已经看见的词) 读作「在已经看见这些词的前提下，下一个词的概率」。

常见卡住

  • 「隐藏维度 768」听着玄。——它就是「每个词用 768 个小数来表示」。没有更深的秘密。
  • 「参数 64M」听着玄。——就是模型里大约 6400 万个可学习的小数。训练就是改这些数。
  • 某一段突然出现三个新缩写。——先打开术语表查，再往下读。不要硬背。
  • 代码能跑但不知道对不对。——先 assert 形状，再打印一个 [0, :3, :4] 这样的小切片，用眼睛看。

自测

合上这一章前，确认你能用自己的话回答：

  • [4, 8, 768] 怎么用中文念？
  • 为什么第 5 章可以暂时没有位置编码？
  • 「从零」包含注意力实现，但不包含重写 AdamW，这样划界是否合理？
  • 你准备把代码写在哪个文件里，才能让第 4 章的归一化被第 5 章直接调用？
自测答案（先自己想）
  1. 4 句话，每句 8 个词元，每个词元 768 个数。
  2. 位置编码只改变查询和键的数值，不改变「用查询检索键、再按分数提取值」这件事本身。先把检索写对，再加位置，不容易缠在一起。
  3. 合理。我们要搞懂 MiniMind 自己独特的结构；矩阵乘法和自动求导是 PyTorch 的基础设施，重写它们对理解这台机器没有帮助。
  4. 同一个包里的模块即可，例如 minimind3/norm.py 被 minimind3/attention.py 导入。不要每章一个孤立脚本互相 copy。
