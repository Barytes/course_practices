第四部 · 训练

第 15 章 · 对话模板与监督微调

预训练会接龙，还不会当助手。监督微调（SFT）继续做下一个词预测，但文本换成「用户 / 助手」模板，并且只在助手要说的那些词元上算损失。

这一章只要记住

从预训练权重接着训，学习率降到 1e-5。用户说的话标签全是 -100，只有助手回复（含结束符）产生梯度。展开对话请调用分词器的 chat_template，不要手拼字符串。

预训练和微调的相同与不同

相同：还是交叉熵，还是同一个 MiniMind-3，还是 AdamW。不同有三处：

  1. 初始权重。从 pretrain_768.pth 加载。学习率降到 1e-5 量级，免得把已经学到的语言知识冲掉。
  2. 数据。jsonl 里是 conversations 列表，角色为 user / assistant / system / tool。
  3. 损失掩码。用户说的话、系统提示、填充，标签都是 -100。只有助手回复产生梯度。

生活比喻

老师批改时把「学生问了什么」那几行用红笔圈掉不记分，只看「你作为助手怎么答」。若对提问也算分，模型会去模仿用户怎么提问，助手风格就不稳。

对话模板把角色变成特殊标记

训练时 add_generation_prompt=False，因为样本里已经包含助手回复。推理时改为 True，模板会在末尾补上 <|im_start|>assistant，模型从这里开始续写。

现在动手 · 写到哪里

文件追加到 exp-2-2/minimind3/data.py
符号函数 generate_labels(input_ids, bos_id, eos_id, max_length)。完整 SFTDataset 可对照官方 dataset/lm_dataset.py，教学上先把掩码写对。
怎么验用一条两轮对话打印：用户字对应 label 应是 -100；助手字应等于该位置的 input id。

掩码怎么对上原理

  • 一开始 labels 全是 -100 → 「默认不算分」。
  • 扫到 bos_id（助手段开始那一小串编号）之后才开始抄 input_ids → 「从助手开口算起」。
  • 抄到 eos_id 含结束符 → 「助手说完的那个结束标记也要学，否则生成不会停」。
  • 用户段、system 段永远匹配不上 bos_id，保持 -100 → 「提问不记分」。

bos_id 是把 bos_token + "assistant\n" 编成的那一小段 id；eos_id 是 eos_token + "\n"。模板一改换行，这两串对不上，标签会全变成 -100，损失假下降。

训练脚本几乎就是预训练脚本换皮：from_weight=pretrain，learning_rate=1e-5，保存前缀 full_sft。循环内部仍然是 loss + aux_loss。

自测

  • 推理时为什么必须 add_generation_prompt=True？
  • 若 bos_id 匹配失败，标签会变成什么样？损失还能降吗？
  • 为什么工具样本不要随机插入 system 提示？
自测答案（先自己想）
  1. 否则字符串停在用户说完，模型不知道该以助手身份续写，可能接着扮演用户，或乱接。
  2. 标签全是 -100，交叉熵被 ignore_index 跳过，损失可能是 nan 或假的 0，参数几乎不更新。
  3. 工具样本里的 JSON 结构被随机插入打乱后，模型学到的调用格式会坏掉。
