第四部 · 训练

第 14 章 · 损失、数据与预训练

结构已经能前向。预训练让它在普通文本上学会「高质量地词语接龙」。这一章把交叉熵、数据格式和训练循环写成你可以对照官方脚本理解的版本。

这一章只要记住

每个位置做一次「6400 选 1」的分类。正确答案是下一个词。padding 的标签写成 -100，不算分。数据每行一个 json，字段叫 text。

交叉熵在语言模型里具体指什么

每个位置，模型给出词表上 6400 个分数。把正确那个词元的编号当作类别，做一次分类交叉熵。序列上所有有效位置求平均，就是这条样本的损失。

生活比喻

老师把下一格的标准答案捂住，让你从 6400 个词里猜。猜得越不准，扣分越多。空出来凑齐长度的格子（pad）老师 squint 一眼直接跳过，不记分。

L = − Σt∈有效位置 log pθ(xt+1 | x≤t)
padding 位置的标签是 -100，PyTorch 的 ignore_index 会跳过它们。

第 12 章已经写了错位。长度为 4 的样本在脑子里走一遍：

位置输入词元该位置 logits 去预测标签
0bos第 1 个词第 1 个词
1第 1 个词第 2 个词第 2 个词
2第 2 个词eoseos
3eos / pad（被切掉，不预测）（被切掉）

预训练数据长什么样

  1. 用分词器把 text 编成编号，截断到 max_length - 2，给 bos/eos 留位置。
  2. 两端加上 bos、eos。
  3. 右边用 pad 填到固定 max_length。
  4. labels = input_ids.clone()，再把 pad 位置改成 -100。

把真实 jsonl 按 MiniMind 文档下载到 minimind_dataset/。没有真实语料时，先用几条短 jsonl 把循环跑通。

数据文件exp-2-2/minimind_dataset/，不要提交进 Git

数据集怎么对上原理

  • 只读 ["text"] → 预训练没有 user/assistant，就是一段话。
  • max_length - 2 再加 bos/eos → 两端结构标记也要占格子。
  • labels = ids.clone() 再把 pad 改 -100 → 「空格子老师不记分」。bos、正文、eos 都算分。
  • 真正的「右移一位」在第 12 章 MiniMindForCausalLM.forward 里，数据集不用再自己错位。

训练一步怎么对上原理

  • loss + aux_loss → 稠密时 aux 是 0 张量；MoE 时带上负载均衡。
  • 除以累积步数再反向 → 显存不够就把 batch 拆开，等效大 batch。
  • 梯度裁剪阈值 1.0 → 防止某批噪声把更新打飞。
  • 预训练 from_weight='none' → 随机初始化，学习率 5e-4，比微调大一个数量级。

官方默认：epochs=2，batch_size=32 再乘 accumulation_steps=8，max_seq_len=340，dtype=bfloat16。没有 GPU 时，用几十条样本确认损失下降即可。

损失从刚开始的大约 ln(6400)≈8.76（接近均匀乱猜）往下降。降到 3 附近时，贪心解码已经能接出「像中文的片段」，但还不会问答。

自测

  • 为什么 bos 位置的标签是「第一个正文词元」，而不是 bos 自己？
  • aux_loss 在稠密模型上是 0，为什么训练循环仍然写成 loss + aux_loss？
  • 若忘记把 pad 改成 -100，损失会被怎样污染？
自测答案（先自己想）
  1. 位置 0 的工作是猜下一个词。下一个词是正文第一个词，不是 bos 自己。
  2. 同一套循环要同时跑稠密和 MoE。aux 为 0 张量时加法是空操作，不必写两套脚本。
  3. 模型会把「猜 pad」当成目标，大量梯度浪费在填充上，有效词的学习被稀释，还可能学会一直输出 pad。
