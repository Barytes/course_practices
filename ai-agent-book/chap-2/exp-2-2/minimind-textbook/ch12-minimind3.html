第三部 · 拼装

第 12 章 · 拼装 MiniMind-3

把嵌入、8 层积木、最终归一化、输出层接成完整稠密模型。写完这一章，你就已经有了 MiniMind-3 的前向计算。

这一章只要记住

两个类：MiniMindModel 负责「编号→8 层→隐藏状态」；MiniMindForCausalLM 再加输出层算 logits 和交叉熵。位置表按缓存里的 start_pos 切片。

两层包装

  • MiniMindModel：词嵌入 → 8 层 → 最终 RMSNorm。返回隐藏状态、各层缓存、混合专家的辅助损失（稠密时为 0）。
  • MiniMindForCausalLM：外面再加 lm_head，算 logits 和交叉熵，并实现 generate（generate 放到第 16 章）。

这样拆是为了和 Hugging Face 的因果语言模型接口对齐。属性名必须和官方一致，才能加载 .pth。

现在动手 · 写到哪里

文件exp-2-2/minimind3/model/model_minimind.py。第 3 章讲的 embed_tokens / lm_head 就写在这两个类里，不要另建 EmbedAndHead。
先写类 MiniMindModel：embed_tokens、layers、norm、两张 freqs buffer、forward
再写类 MiniMindForCausalLM：self.model、lm_head、权重共享、forward 里的错位交叉熵
怎么跑cd exp-2-2/minimind3 后 python -c "from model.model_minimind import MiniMindForCausalLM"。参数量应约 64M；logits.shape == (2, 16, 6400)

MiniMindModel 怎么对上原理

  • embed_tokens(input_ids) → 第 3 章查表，[B, T] 变成 [B, T, 768]。
  • ModuleList([MiniMindBlock(i, ...) for i in range(8)]) → 第 1 章图纸上的「×8 层」，每层自己的权重。
  • start_pos = past_key_values[0][0].shape[1] → 第 8 章：有缓存时位置从已经写过的长度接着数，不从 0 开始。
  • freqs_cos[start_pos:start_pos+seq_length] → 把预计算表切给当前这段查询。注意力内部不要自己 arange。
  • zip(self.layers, past_key_values) → 第 11 章：每一层拿自己的那一格缓存，写回 presents 同一格。
  • 层后再 self.norm → 第 4 章说的「整网输出前再来一次」。
  • 稠密时 aux_loss 用 sum(..., zeros) 得到 0 张量 → 训练循环统一写成 res.loss + res.aux_loss。
  • if self.freqs_cos[0, 0] == 0 → transformers 5.x meta 设备初始化会把 buffer 清零，官方会重算 RoPE 表。不要删这几行。

标签相对输入右移一位

用位置 t 的隐藏状态预测位置 t+1 的词元。官方在模型内部完成这次错位。

外壳怎么对上原理

  • 权重共享那两行 → 第 3 章，省 491 万参数。
  • logits[..., :-1] 对 labels[..., 1:] → 「用位置 t 猜位置 t+1」。最后一个位置的 logits 在这次错位里用不上；生成时恰好只要最后一个位置。
  • MoeCausalLMOutputWithPast → 官方训练脚本写 res.loss + res.aux_loss、outputs.logits。不要返回元组，否则 trainer/train_pretrain.py 和 eval_llm.py 都会坏。
  • PreTrainedModel, GenerationMixin → 才能 load_state_dict 官方 .pth，并调用本类的 generate。

若参数量接近 69M，多半是嵌入没有共享。若只有十几 M，多半是层数或中间维没读配置。

本章完成的标志

MiniMindConfig(use_moe=False) 能做一次前向，交叉熵是有限标量，参数量约 64M。还不会说话——那是第 14 章训练之后的事。结构已经是 MiniMind-3。

自测

  • 8 层的 past_key_values 是长度 8 的列表，还是一个大张量？每一格里是什么？
  • 为什么最终 RMSNorm 在 8 层之后、lm_head 之前？
  • labels 已经与 input_ids 对齐存放时，为什么还要在 forward 里对 logits 取 [:-1]、对 labels 取 [1:]？
自测答案（先自己想）
  1. 长度 8 的列表。每一格是该层的 (K, V) 元组，形状里序列维会随生成增长。
  2. 8 层已经把表示加工完，输出层前再拉一次尺度，logits 更稳。不必每层末尾再来一次——层内已经有预归一化。
  3. 位置 t 的隐藏状态应对「下一个词」负责。两边各切掉一格，才能一对一对齐。不切的话，模型会学成「看见自己猜自己」。
