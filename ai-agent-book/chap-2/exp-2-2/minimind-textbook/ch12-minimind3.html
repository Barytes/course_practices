第三部 · 拼装

第 12 章 · 拼装 MiniMind-3

把嵌入、8 层积木、最终归一化、输出层接成完整稠密模型。写完这一章，你就已经有了 MiniMind-3 的前向计算。

两层包装

官方拆成两个类，职责不同：

  • MiniMindModel：词嵌入 → 8 层 → 最终 RMSNorm。返回隐藏状态、各层缓存、混合专家的辅助损失（稠密时为 0）。
  • MiniMindForCausalLM：外面再加 lm_head，算 logits 和交叉熵，并实现 generate。

这样拆是为了和 Hugging Face 的因果语言模型接口对齐。教学上可以先把两者写在同一文件，但请保持同样的调用关系，后面接训练脚本时才不用改。

MiniMindModel：位置表 + 层循环

稠密模型没有 MOEFeedForward，辅助损失保持 0。官方用 sum(..., hidden_states.new_zeros(1).squeeze()) 保证即使 0 也是一个真正的标量张量，能和主损失相加。

freqs 变成全 0 怎么办

官方有一段：若 self.freqs_cos[0, 0] == 0 就重新预计算。这是为了兼容某些「meta 设备」初始化（先在空设备上建图再搬到 GPU，buffer 会丢）。你在普通 .to(device) 流程里可以先不写；一旦发现旋转没生效，再把这段补上。

MiniMindForCausalLM：logits 与训练损失

标签相对输入右移一位：用位置 t 的隐藏状态预测位置 t+1 的词元。官方在模型内部完成这次错位，数据集可以返回「对齐后的 input_ids 与 labels」，padding 处 labels 为 -100。

官方返回 MoeCausalLMOutputWithPast 这个命名元组，便于 res.loss、res.aux_loss 取值。教学版返回元组即可；训练循环写成 loss = res[0] + res[1]。

logits_to_keep：生成时往往只需最后一个位置的分数。设为 1 时只对最后一格做 lm_head，省计算。训练时保持默认 0，表示「从 0 到末尾都保留」，再在内部用 [:-1] 对齐标签。

现在立刻做的形状与参数检查

若参数量接近 69M，多半是嵌入没有共享，输出层又算了一份。若只有十几 M，多半是层数或中间维没读配置。

和官方类的差异清单

官方你可以暂时简化不要简化
继承 PreTrainedModel, GenerationMixin普通 nn.Module前向计算顺序

若你希望直接加载官方 .pth，模块树的名字必须一致：model.embed_tokens、model.layers.0.self_attn.q_proj、model.layers.0.mlp.gate_proj、lm_head……最稳妥的办法是把官方 Attention / FeedForward / MiniMindBlock 的属性名原样抄下来。

自测
