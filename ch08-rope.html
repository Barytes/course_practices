第 8 章 · 旋转位置编码

到目前为止，注意力把序列当成「一组无序卡片」——打乱词序，分数几乎不变。旋转位置编码把位置写进查询和键的几何里，让点积自动带上相对距离。

这一章只要记住

不把「第几个词」直接加到输入上，而是在算注意力之前把 Q 和 K 按位置旋转。V 不转。新词用新位置的 cos/sin；旧键在缓存里已经带着旧旋转，不能再转一次。

没有位置信息会怎样

「狗咬人」和「人咬狗」若只是同一袋词元，自注意力无法区分。早期做法是在嵌入上加一份绝对位置向量。更好的做法是：不往输入上加东西，而是在算注意力之前旋转 Q 和 K，使得

(Rm q) · (Rn k) = q · (Rn−m k)
位置 m 的查询与位置 n 的键的点积，只依赖于相对距离 n−m，以及 q、k 本身。

生活比喻

两根指针。把它们按各自所在的时刻针旋转之后再比角度，比出来的是「相差几个小时」，而不是「现在是几点」。这就是相对位置。正文（V）不必跟着转，否则内容本身被拧歪了。

这就是旋转位置编码（Rotary Position Embedding，RoPE）。MiniMind-3 和 Qwen3 都用它。

二维旋转，推广到 96 维

平面上把向量旋转角度 θ，可以用一个 2×2 矩阵。RoPE 把 head_dim 维两两一组，每一对用不同的频率旋转。第 i 对的频率是

ωi = θbase−2i / head_dim　　i = 0, 1, …, head_dim/2 − 1
MiniMind-3 的 θ_base 即 rope_theta = 1e6。较大的基频让高频（近距离）和低频（远距离）分得更开，有利于长上下文。

位置 m 上，第 i 对被旋转 m · ωi。低频那几对转得很慢，即使 m 很大，两个位置的相对角也还能分辨；高频转得快，负责近距离的精细差别。

现在不必手算 96 维。记住：频率表的 dim 必须是 head_dim=96，不是 768。

官方用「一半对一半」而不是交错偶数奇数

旋转的实现有两种常见布局：

  • 交错：维度 0 和 1 一对、2 和 3 一对……
  • 对半：前一半维度和后一半维度配对，即 (-x[..., d/2:], x[..., :d/2])

MiniMind 用第二种，与许多 Hugging Face 实现一致。V 不旋转：值是「内容」，位置只应影响「能不能匹配」。

旋转插在哪一步

正确顺序是：

  1. 线性投影，reshape 成 [B, T, 头数, 96]。
  2. 查询/键归一化（下一章）。
  3. 旋转 Q 和 K。此时还是「头维在后」的布局。
  4. 拼接键值缓存。
  5. repeat_kv，再 transpose 去算分数。

先旋转再拼接：新词用新位置的 cos/sin，旧键在缓存里已经带着旧位置的旋转，不能再转一次。

现在动手 · 写到哪里

新文件exp-2-2/minimind3/rope.py。三个函数都写在这里：rotate_half、apply_rotary_pos_emb、precompute_freqs_cis。
改注意力minimind3/attention.py 的 forward：在 reshape 之后、拼接缓存之前，调用 apply_rotary_pos_emb。需要新增参数 position_embeddings=(cos, sin)。
谁切片 cos/sin现在可以在注意力外部用 freqs_cos[start_pos:start_pos+seq_len] 传进来。第 12 章会把预计算表挂到 MiniMindModel 上。本章先在 rope.py 的 __main__ 里自测形状。
不要写不要在注意力内部用 torch.arange(seq_len) 现造位置——有缓存时会永远从 0 开始。

rope.py 怎么对上原理

  • rotate_half → 「前一半和后一半配对」：后一半取负，再和前一半对调。这就是二维旋转在实数张量上的写法。
  • q * cos + rotate_half(q) * sin → 复数乘法 (q_cos + i q_sin) * (cos + i sin)。位置写进了 Q、K 的几何。
  • 只返回旋转后的 q、k，没有 v → 「正文不转」。
  • precompute_freqs_cis(dim=head_dim) → 预先算好每个整数位置的 cos/sin，训练时当常数表用，不进优化器。
  • torch.cat([cos, cos], dim=-1) 把半长表拼回 96 维 → 和「一半对一半」的布局配套。

插入位置怎么对上原理

  • 先转再拼接 → 新词用新位置的角度；旧键缓存里已经转过，不会被转第二次。
  • unsqueeze_dim=1 → cos/sin 形状 [T, 96]，插一维后能广播到每个头。
  • 外层负责 start_pos → 生成第 21 个词时必须用位置 20 的 cos，而不是位置 0。

频率表的 dim 是头维度

写 precompute_freqs_cis(dim=config.hidden_size) 是错的。必须是 config.head_dim。传 768 时，你会在 96 维的 Q 上广播失败或静默算错。

YaRN：推理时把位置「拧松」

模型若在长度 2048 上训练，直接推理 8192 会让旋转角度跑出训练分布。YaRN 把一部分频率按比例压低。教学实现可以先不管：rope_scaling=None 时就是上面那几行。需要外推时，把官方函数里 if rope_scaling is not None 那一段原样拷入即可。

自测

  • 为什么旋转 V 是错的？
  • 生成第 2 个新词时，若 cos 仍取 freqs_cos[0:1] 而不是 freqs_cos[start_pos:start_pos+1]，相对位置会怎样？
  • 对半旋转里，若误写成交错版，能否和官方权重兼容？
自测答案（先自己想）
  1. V 是被提取的内容。位置只应影响「匹不匹配」，不应把内容本身拧歪。Q、K 旋转已经把相对距离写进点积了。
  2. 每一步都以为自己站在位置 0，相对距离全错，「狗咬人」和「人咬狗」又分不清了。
  3. 不能。权重是按「一半对一半」的布局学出来的。交错版旋转的是另一对维度，数字对不上。
