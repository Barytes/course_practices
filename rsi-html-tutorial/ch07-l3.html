第二部 · 五级阶梯

第 7 章 · L3：自己决定下一课学什么

L2 决定怎么改。L3 额外决定学习议程：根据自己现在会什么、哪里失败、学过什么，选择、生成或寻找下一份经验。学完以后的状态，还会再塑造以后的取经。

这一章只要记住

关键词是以学习者为条件的未来经验。只是政策更新后碰巧走到新状态，不算。一次性过滤数据也不算。要形成：学习者状态 → 选经验 → 持久学习 → 再改变下次选经验。

先分清「自动造数据」和「自己排课」

工业数据流水线已经能自动做很多事：准备数据源、打标、筛选、构造、混合与编排、根据模型反馈诊断。Dolma、Yi、Qwen、Phi-4 的公开材料显示，摄入、过滤、样本生成一旦输入和录取标准给定，就可以规模化跑。

这仍然可以是 L1：人规定数据政策和混合策略，流水线执行。L3 要额外证明一件事：学习者正在变化的反馈，自主改变了下一课学什么，而不需要人在每一轮后重新设计课程。

固定的选择算法也可以产生适应的学习议程——只要它吃的是变化中的学习者反馈。反过来，自动造了再过滤的新样本，若与学习者状态无关，也不构成经验自治。

经验不必从零生成。从外部题库里反复选题，只要选择跟着学习者走并进入持续的环，也可以。持久学习可以在参数里，也可以在记忆和技能里。

两条互补的组织方式：自适应出题 / 自博弈；在环境里自主练习。

自适应出题与自博弈

学习者变强以后，同一道题的价值会变。太熟没有信息，太难没有可用信号。自适应生成用依赖学习者的信号，估计哪些题还撑得起下一次进步。

三个连着的挑战：拿到有信息量的信号；把它翻译成有用的题分布；保住经验的有效性（题得能判对错）。

Absolute Zero Reasoner：零外部题目的自博弈推理

Zhao 等人，2025 · arXiv:2505.03335 · 一个模型既当出题人又当答题人

它想解决什么

可验证奖励的强化学习（RLVR）可以不监督推理过程，但通常仍要人准备「题 + 答案」。题总会用完。Absolute Zero 问：能不能让模型自己出对自己刚刚好的题，用代码执行器当唯一的外部世界？

实现怎么走

  1. 同一套权重扮演两个角色。Proposer 出题，Solver 答题。
  2. 题的形式是程序–输入–输出三元组上的三种推理：
    • 演绎：给定程序和输入，预测输出；
    • 溯因：给定程序和输出，反推输入；
    • 归纳：给定若干输入输出，写程序。
  3. Proposer 参考缓冲区里过去的三元组，按指定类型生成一批新题。Python 执行器先检查题本身合不合法（能跑、有确定输出等）。
  4. 用 Monte Carlo：让当前 Solver 对同一题试多次，成功率记为 r̄。可学性奖励：r̄=0（完全不会）时出题奖励为 0；否则奖励为 1-r̄。也就是偏好「有时会、有时不会」的题，讨厌全对或全错。
  5. Solver 的奖励是对错二元，由执行器核对。
  6. 两种奖励一起，用面向多任务的 TRR++（Task-Relative REINFORCE++）更新同一模型。

论文报告：完全不用外部题，编码和数学基准上可以超过用了数万条专家题训练的 zero-setting 模型。这是 L3 的干净例子：出题分布跟着 Solver 的当前能力走，Solver 变强后又改变出题奖励。

技术难点

可学性奖励估计的是「当前 Solver 眼中的难度」，不是「学了以后真能涨多少」。模型可能刷一类容易得到中间成功率的题，课程变窄。执行器只能保证相对于这道形式化题的对错，不能保证这道题对数学推理有用。缓冲区多样性、三种题型的平衡、以及防止出无法判定的程序，都是工程上的硬点。更新规则、任务格式、代码沙箱仍是人定的——所以不是 L5。

留下什么
模型权重，以及作为课程记忆的题目缓冲区。
人还控什么
三种题型、执行器、奖励公式、优化器。

邻近系统用不同信号完成同一件事：

  • SSP（搜索自博弈）：出题人奖励依赖当前解题人表现，搜索题课程不用人每批重写。
  • R-Zero：Challenger–Solver。Challenger 的不确定性奖励来自当前 Solver 多次回答是否一致。没有标准答案时，一致性是难度代理，不是正确性证明。
  • STP：猜想器 + 证明器。当前证明器「勉强能证」的猜想拿去训练猜想器；已检查的证明训练证明器。形式证明助手提供域内正确性。
  • PSV：用解题人导出的难度标签去提示新规格；规格要能编译，解要被形式检查。论文报告易/中/难的实现难度大量重叠——说明「按难度出题」只有部分课程控制力。
  • VisPlay：图像条件的提问者 + 推理者。提问者奖励靠近规定中点的多数票置信度，外加多样性惩罚。同样，信号可扩展，但也可能反映含糊而不是有生产力的难度。

反馈沿两维变化：可执行结果/形式证明能在规定设置里钉住正确性；答案一致性只估计难度。适应可以写在训练好的出题器里，也可以写在生成提示和选择程序里。

在环境里自主练习

交互智能体必须决定下一次学习力气花在哪。再收集轨迹本身不够：无引导探索会重复已会的，固定课表又不能响应新技能或顽固失败。

Voyager：自动课程 + 可执行技能库

Wang 等人，2023 · arXiv:2305.16291 · 仓库 MineDojo/Voyager

它想解决什么

在开放的 Minecraft 里长期生存和学习。不微调 GPT-4，只靠黑盒查询。要能自己提出「下一步练什么」，并把成功行为变成以后可组合的程序。

实现怎么走

  1. 自动课程：另一个 GPT-4 提示读当前物品栏、位置、探索历史、已有技能，提出一个「稍稍超出现在能力」的目标（例如从「打木头」到「造木镐」）。提示里明确要求避免太简单和太离谱。
  2. 技能库：每个技能是一段 Mineflayer 的异步 JS，例如 async function craftWoodenPickaxe(bot)。成功并（可选）再跑一遍确认后入库。
  3. 索引：再让 LLM 给代码写自然语言描述，用描述的嵌入放进 Chroma 向量库。磁盘上同时存 code/*.js、description/*.txt、skills.json。重名则写 nameV2.js。
  4. 检索：新目标到来时，用任务计划和环境反馈的嵌入取 top-k 技能，放进生成提示，让新程序组合旧技能。
  5. 迭代提示：执行环境反馈、JS 异常、自我验证（再问一次「是否真完成」）一起写回，循环改程序，直到成功或预算用尽。

论文数字：独特物品 3.3 倍、旅行距离 2.3 倍、科技树里程碑最多快 15.3 倍。技能库可以整个拷到新世界，从零做新任务——这是「持久状态换环境仍有用」的证据。

技术难点

自我验证会撒谎：模型说合成了，物品栏里没有。环境反馈噪声大（路径被堵）。技能库只增不删会检索退化（这正是后来 L4「库漂移」研究的前身）。课程提示是人写的，Minecraft 接口是人接的。底层 GPT-4 权重不变，持久性在外部技能，不在参数——综述明确说这仍然可以是 L3。

留下什么
可执行技能库 + 探索历史，它们改变下一目标。
人还控什么
游戏接口、课程提示模板、技能表示、何时入库。

SIMA 2 提醒实验设置很重要：固定任务上用自己生成的轨迹训练，只能说明「自我生成数据有用」，不能说明「对任务选择有自治」。完整 ASKA 设置里，Gemini 任务设定器根据下游奖励模型评估，把练习对准更弱的技能。自治属于这个耦合学习系统（含任务设定器），不要求行动模型亲自做每一个课程决定。

SEAgent 面向陌生软件：世界状态模型给轨迹判断和 GUI 状态变化描述，课程生成器更新持久的「软件指南」，再用指南生成以后的任务。Actor 从收集的经验学习，后续互动继续改指南。指南把早期探索带进以后的练习，帮助课程超出已经探索过的操作。

三类资源不同：Voyager 链到探索历史和可复用技能；SIMA 2 链到奖励模型评估；SEAgent 维护一份演化中的软件行为说明。因此，不可靠的技能构造、不准的奖励、错误的指南条目，都会把以后的学习力气带偏。

怎么评价 L3

控制了学习议程 ≠ 学到的经验有用。评估要同时钉住机制和好处：哪个学习者信号影响了取经、什么持久状态因学习而变、这变化如何影响以后的取经决定。

有用的对照：把取经机制的「学习者状态输入」冻在更早检查点；或换成与学习者无关的课表。比较时匹配数据源/环境访问和总预算（含造经验、评估的成本）。如果强行让两边拿到完全相同的样本，就删掉了你想研究的分布适应。

还要分开三件事：正确性、难度、学习收益。形式检查钉住的是规定属性；一致性是易错估计。综述用经验腐蚀称呼这种风险：有缺陷的经验或反馈扭曲以后的学习和取经，并可能写进参数、技能、记忆或课程状态，跨轮传播。

Finding：L3 增加了对未来学习议程的自治。人设计的目标、评测器和学习规则可以仍在；经验自治谈的是这个设置里做的决定，它本身不保证改进有用或可靠。

AZR、R-Zero、Voyager、SIMA 2、SEAgent 的实现细节见 深挖 L3。
