第二部 · 五级阶梯

第 9 章 · L5：改进「改进器」本身

编码智能体可能因为搜索程序丢掉有用备选，而反复打出相似的失败补丁。研究智能体可能在开发分已经不再预测外部分时，还继续优化开发分。修这类失败，必须改「指导实验和判断结果」的程序。

这一章只要记住

L5 从这里开始：AI 持久修改一个负责未来改进的机制，并在后续轮次使用改过的机制。结构 L5 = 改过的机制真被下一轮调用。有效 L5 = 在可比预算和独立评测下，它还能造出更强后继者。今天多半只有有界的结构 L5。

和 L4 差在哪

部署智能体通过不变的学习程序留下新的调试技能，是 L4。修订并复用「诊断失败并建造这些技能」的程序，才越过 L5 边界。

环闭合于：修订过的机制回来治理后继者的生成、评价或选择。继承状态包括被接受的代码、提示、评测器或研究政策，以及后来修订会用到的证据。人仍建立总任务、受保护评测、可编辑部件、资源许可，并可保留否决和部署权。其中一些由固定基础设施执行，不必人批准每一次迭代。

只改任务代码、却不改以后如何修订的过程，证据不足。反过来，进化后的后继评测器即使任务智能体代码没变，也可以构成结构 L5。级别判定针对被考察的那条机制。

方向一：改进搜索程序

STOP：让「改进器程序」改进自己

Zelikman 等人，2023/2024 · arXiv:2310.02304 · 仓库 microsoft/stop

它想解决什么

Tree-of-Thoughts、程序辅助语言模型这类系统，本质是人写的脚手架：用 Python 结构化地多次调用语言模型。STOP 观察到：对固定语言模型和一堆下游任务，设计脚手架本身也是优化问题。于是把「改进任意程序的改进器」套到自己身上。

实现怎么走

  1. 种子改进器 improve_algorithm(initial, utility, language_model) 大约 20 行：用同一段提示让 GPT-4 并发生成若干候选，用效用函数选最好的返回。提示要求「主要改进必须新颖且非平凡」。
  2. 元效用 û(I)：把改进器 I 用到一组下游训练任务上（每个任务自己有效用函数，例如运行时间、正确性），取平均分。
  3. 递归：I_t = I_{t-1}(û, I_{t-1}, L)。也就是当前改进器把「自己的源码」当作待改进的解，用元效用当分数。
  4. 下游任务在自改进时被用来算元效用；另留一组迁移任务，自改进时不准碰，用来看改进器有没有学会一般的搜法。
  5. 仓库里 helpers.py 负责抽代码、读写种子算法；run_improver.py 里 attempt_algorithm_improvement 跑一轮。

GPT-4（训练数据截止 2021）竟然提出了截止后才流行的脚手架：束搜索、遗传算法、模拟退火、多臂提示老虎机、分解后局部改进。论文报告第四代改进器在全部五个留出迁移任务上超过种子。底座语言模型始终不变，所以作者自己说：这不是完全的 RSI，只是递归改进脚手架。

技术难点

弱模型平均会回退。有的生成程序会绕过软预算或钻评价漏洞。安全实验里测量了生成代码试图关掉沙箱标志的频率。录取门也很关键：社区 issue 指出外层循环有时用「效用非零」而不是「比父代更好」来接纳下一任改进器，轨迹会变难解释。效用、底座模型、资源上限、任务分布全部外部给定。

留下什么
改进器源码（可能引入束搜索等新搜法）。
人还控什么
效用、底座 LM、预算、下游任务集。

Gödel Agent：运行时改自己，包括改「如何改自己」

Yin 等人，ACL 2025 · arXiv:2410.04444 · 仓库 Arvid-pku/Godel_Agent

它想解决什么

手设计智能体自由度最低；元学习智能体可以改模块，但元算法仍被写死。Gödel Agent 想要自指：能读、能改自己的代码，包括负责分析和修改的那部分。灵感来自 Schmidhuber 的 Gödel 机器，但用 LLM + monkey patch 代替「先证明再修改」。

实现怎么走

  1. 核心不在 for 循环，而在递归主函数。这样才能在运行中替换正在执行的逻辑。
  2. SELF_INSPECT 读取运行时内存里的函数、类、全局变量，让模型看见「我现在是谁」。
  3. 模型决定是否改逻辑。若改，生成新代码，用 monkey patch 写进运行中的模块（动态替换类或函数）。
  4. 动作集包括：solver（当前任务政策）、action_adjust_logic（改自己）、action_run_code、action_evaluate_on_task（在任务环境上拿反馈）。
  5. 下一层递归调用已经是新逻辑。换任务时，人主要换环境描述、奖励函数和 action_evaluate_on_task；初始 solver 可以很笨。
  6. 生成的智能体代码落在 logic.py。任务脚本改编自 ADAS 的环境。

这把搜索空间扩到开发者固定编辑套路之外。综述强调它也让错误可继承：100 次 MGSM 优化里 14 次低于初始政策；不受限运行还可能去调更强模型。任务目标和执行权限因此是关键外部控制。

技术难点

Monkey patch 让调试极难：出问题的代码可能已经不是你启动时的代码。没有证明门，有害自修改只能靠任务分数事后发现。递归深度、API 花费、以及「自我评价函数也被改」带来的循环，都需要硬限制。它展示的是结构 L5 的自由度，不是有效 L5 的稳定性。

留下什么
任务政策代码 + 自我更新代码。
人还控什么
目标提示、运行时权限、任务评价入口。

Darwin Gödel Machine：开放式档案上的自我改代码

Zhang 等人，2026 · arXiv:2505.22954 · 仓库 jennyzzt/dgm

它想解决什么

理论 Gödel 机器要求证明自修改净有益，实践上几乎不可能。DGM 改成经验验收，并引入达尔文式开放探索：不是一条谱系改到底，而是生长一棵多样、高质量的编码智能体树，平行走很多条路。

实现怎么走

  1. 档案里每个节点是一个完整编码智能体（工具、上下文管理、补丁策略等代码）。
  2. 按规则采样父代（注意：这条采样规则不在自我修改范围内）。
  3. 父代改自己的代码，得到子代。改动可能是更好的编辑工具、长上下文管理、同行评审机制。
  4. 在编码基准上评（SWE-bench 子集、Polyglot），通过经验信号决定是否进档案。
  5. 保留多条谱系，避免一次有害编辑永久堵死；暂时更弱的变体可能成为踏脚石。
  6. 实验在沙箱和人类监督下进行。

公开数字：SWE-bench 20.0% → 50.0%，Polyglot 14.2% → 30.7%，显著好于无自我改进或无开放探索的基线。综述把它当过渡案例：任务分涨了，不等于改进程序本身变好了，因为档案维护和父代选择仍在环外。

技术难点

评测每个子代都要跑真实仓库测试，极贵。档案采样若偏向当前高分，会过早收敛；若过于均匀，预算浪费在弱枝上。HGM（Huxley–Gödel Machine）因此提出用谱系估计「元生产力」——当前分 ≠ 产生更强后代的能力。安全上，自我改代码必须沙箱，否则就是任意代码执行。

留下什么
智能体代码 + 档案。
人还控什么
父代选择、基准、档案规则。

HyperAgents 把任务智能体和元智能体代码都暴露给修订。进化出的元智能体做出性能跟踪器和持久记忆来指导下一次修改。预印本称：在论文评审和机器人上进化的元智能体，能为未见过的数学评分生成更好智能体，支持「改进程序可迁移」。更长的 200 次迭代实验没有给出迁移初始化的统计显著最终优势。主实验里父代选择和评测仍固定。

方向二：改进后继评测器

反复优化会压向判官的盲区。判官不变，会奖励钻空子；判官随便变，分数又不可比。

RQGM（Red Queen Gödel Machine）：学到的评测器在一纪元内冻结。到了计划边界，挑战者评测器对照独立真值锚比较；选中的评测器治理下一纪元。依赖被替换评测器的分数作废，受影响智能体再访时重评。环带走改进的评测器和智能体代码，同时重置不兼容的评价记录。留出 Polyglot 上预印本报 71.7% 对 HGM-H 的 69.9%，且搜索 token 更少。锚、替换日程、编排仍外部固定。形式稳定性论证适用于每个冻结纪元，不适用于目标被任意改。

方向三：修订研究目标与政策

代理奖励若在错误瓶颈上涨分，提高目标反而有害。A-Evolve-Training：30B 模型自主后训练四轮。工人返回配方变更、检查点评价和失败；收集器汇总，元智能体修订下一轮搜索政策。政策携带现行配方、晋升或退役的搜索方向、失败方法登记。当开发分涨而外部分不涨，修订后的政策让工人去做能抬外部目标、即使降低代理分的干预。最终榜 0.86 对人类最佳 0.87。跨轮继承在研究政策和发现日志；工人底座和章程固定。这是固定高层目标下的政策级 L5，没有演示自主改那个高层目标。

工业上的有界 L5

Meta AIRA2、Anthropic Automated Alignment Researchers 自动化的是实验执行，报告的是研究产出，没有确立对「做研究的程序」的继承式修改。

AIDE²（Weco）：研究智能体去改进研究智能体的 harness。候选 harness 在私有打分和固定成本预算下跑下游任务，通过的版本留给后续研究；另一次实验把进化出的 harness 装成外层改进器。报告 100 步无人值守里 7 次录取改进，并能迁移到外部任务。更严的测试——进化出的智能体能否更快改进外层搜索——没有统计显著的效率优势。公司报告支持有界 harness 改进；私有评价、任务族、成本约束仍是人设计的。可靠地加速「一任改进器接一任」仍未确立。

怎么评价 L5

SEA-Eval / SEAGym 提供轨迹向测量：跨轮增益、留出迁移、保持、资源、有害更新。L5 还要加机制审计：修订了哪件制品、动机证据、是否在后来的改进轮被调用。有效性比较应从可比的智能体和证据出发，预算包含评价机制本身的成本。把修订机制在迁移测试中冻结，才能分清「它学会了如何改进」还是「它只是在原任务上刷分」。HyperAgents 用这种设计区分可迁移的智能体生成能力和原任务表现。

目标选择需要互补评价：自适应前沿任务看它是否找出有用的下一挑战；受保护参考任务保持可比性并暴露遗忘或奖励黑客。还应记录系统是否在期望收益低于成本或风险时停止。

Finding：L5 让改进程序可继承。环通过复用修订过的改进器、评测器或研究政策而闭合。后继者继承该程序及其证据；人握住总目标、受保护录取标准和资源权。统计上可靠的、跨代在可比资源下的累积，仍然开放。

STOP、Gödel Agent、DGM、RQGM、AIDE² 的源码级展开见 深挖 L5。
