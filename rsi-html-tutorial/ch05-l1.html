第二部 · 五级阶梯

第 5 章 · L1：按说明书执行改进

人规定目标、更新步骤和录取标准，AI 去执行。和 B0 的唯一本质差别：通过验收的产物会写进系统，下一场任务还能用。

这一章只要记住

L1 的环是：接到改进目标 → 执行规定步骤 → 产出改进 → 更新系统状态 → 处理下一任务 → 重复。AI 还不能改说明书本身。

先建立分工

Meta 的产能效率系统是一个很好的生活化例子：工程师把排障经验写成可复用的修复技能，智能体按预定程序诊断性能回退并做补救。小时级的人工排查被压到分钟级，产出的 PR 仍走标准评审。持久改进发生在生产系统里，但「何时用哪条技能、怎样算修好」仍是人预先编码的。

L1 听起来简单，可靠执行却有三个核心难点：

  1. 说明书必须覆盖执行时遇到的情况。没写到的分支，智能体没有下一步，也不能自己改说明书。
  2. 多步流程里，一次误诊会污染后面所有动作。
  3. 产物要写回系统再给以后用，所以留下前必须检查；否则执行错误会变成长期缺陷。

下面按「AI 开发流水线」六层看代表实现。每一层人都先把经验写成步骤，AI 负责规模化执行。

数据层：人定标准，模型打标签

训练语料大到无法逐条人工看。数据策展因此从「人看每一条」变成「人定义什么叫好，模型按这个定义去筛」。

FineWeb-Edu：用合成标注训练一个「教育味」分类器

Penedo 等人，2024 · arXiv:2406.17557 · 综述 L1 数据过滤的标准例

它想解决什么

网页很多，但真正适合当教材的少。人无法给 15 万亿词元逐条打分。需要一种可重复的「教育质量」过滤器。

实现怎么走

  1. 研究者写好评分标准：0–5 分，关注中小学能懂的知识，避免模型偏爱 arXiv 那种过专的页。提示采用「逐条加分」而不是一次性打类别，让 Llama-3-70B-Instruct 逐步累加分数。
  2. 从 FineWeb 随机抽约 46 万网页，让 Llama 3 按该提示打分，得到合成标注。
  3. 在 Snowflake-arctic-embed-m 嵌入模型上面接一个线性回归头。嵌入和编码器冻结，只训回归头：41 万条训练、20 个 epoch、学习率 3e-4；剩下约 5 万条当验证集，按 Llama 标注当「真值」选 F1 最高的检查点。
  4. 把回归输出四舍五入成 0–5 的整数。阈值取 3：大于等于 3 的留下。验证集上当二分类时 F1 约 82%。
  5. 用这个小分类器扫完整 FineWeb（公开材料称约 6 千 H100 小时），得到 1.3 万亿词元的 FineWeb-Edu。

为什么不直接让 Llama 3 给全部网页打分？因为太贵。L1 的典型结构就是：贵模型当老师打一小撮标签，便宜模型当工人复制这个标准。

技术难点

标准本身是人写的：换一句「不要偏爱技术页」，留下的语料分布就会变。分类器会继承 Llama 3 的偏见，也可能过拟合「看起来像教材」的表面特征。阈值 3 和阈值 2 是精度–召回的权衡（后者保留 5.4 万亿词元，推理类分数稍弱）。分类器不会自己决定「明天改用另一套教育定义」——那一步仍是人的。

留下什么
过滤后的预训练语料，以及可复用的分类器权重。
人还控什么
教育定义、提示、阈值、是否采用该数据集训练下游模型。

同一分工还出现在：Google 高保真标签策展（LLM 初标 + 聚类找边界样本再请专家看）、Phi-4-reasoning 的能力边界样本筛选、NVIDIA NeMo Curator 的可配置过滤模块、Data-Juicer 的可组合算子。合成监督则有 Microsoft SynthLLM（从优质网页抽概念再生成问答）、SynthAgent（网页探索→任务→轨迹）、Nemotron-4（指令模型生成候选，奖励模型按人定维度过滤）。细节卡片见 深挖 L1。

训练方法层：把诊断手册编进训练

EDIT 把「找出坏的推理步，只改坏的部分」写成两段式训练：人规定诊断信号和修订量规，系统定位问题步骤，LLM 按清单修订，修订结果再拿去强化学习校准。REPO 则把多阶段 SOP 和行为约束写进多轮互动，用 LLM 评委按人定标准打「有没有按规定走」，再把分数变成奖励。

难点是诊断标准一旦写错，错误会被规模化写进权重。L1 放大的是说明书的质量，好说明书能省人，坏说明书能污染整个后训练。

训练平台层：按 runbook 修分布式故障

Agent-Agnostic C/C++ 性能优化把完整优化控制环放进程序性记忆：运行分析 → 找热点 → 生成候选修改 → 按预定义工作流验收正确性和性能 → 失败则回滚。Meta 与 PyTorch 社区把 NCCL watchdog 超时的根因整理成决策树和调试 runbook，智能体按这份树在具体故障上对齐各 rank 证据、追踪集合通信序列、把运行时轨迹连到代码路径，找到最早可行动的分叉。

难点：真实故障经常落在 runbook 没写到的组合里。智能体不能改 runbook，只能失败或幻觉出一步。留下的修复如果没经验证，会变成「生产里的永久补丁」。

评测与安全层：专家量规，模型打分

HealthBench 请医学专家为具体医疗对话写下细量规：理想回答必须包含/避免什么、各条的相对重要性。然后用 GPT-4.1 按这些量规给候选回答打分。人仍然定义目标、标准和录取阈值；AI 负责把专家判断复制到大规模输出上。

难点：量规再细也覆盖不了所有临床情境；模型评委可能比人更严或更松（Lark 后来也报告过自动评委偏严）。L1 评测的产品是「可重复的分数」，不是「评测器自己进化」——后者是 L5 的 RQGM 要碰的问题。

部署与应用层：技能包和工程剧本

  • AIPC：把模型转到 Qualcomm AI Runtime 的转换、兼容性、量化校准、分阶段校验写成 Agent Skills，智能体按阶段执行，产出可运行制品。
  • AWS Agent Toolkit / LinkedIn CAPT：把组织里的集成步骤、建服务、改接口写成可执行剧本，编码智能体在真实代码库里走这些步骤。
  • OpenAI Harness Engineering：工程师定义产品意图、架构、CI/合并/回滚规则，Codex 在这些约束里实现和验证，持续产出进入后续开发流的代码。

这些系统已经能完成很长、后果很重的步骤。它们仍是 L1：流程本身不能被 AI 改写。

怎么评价 L1

要一起看两件事：

  • 执行可靠性：条件一变，还能不能按说明书做对。
  • 持久安全性：执行引入的错误会不会在留下之前被拦住。

Finding（综述原意）：L1 把已有工程经验编码成明确步骤和验收规则，AI 在具体任务上执行，产物进入后续工作流，同一套程序可以在独立任务和开发阶段上反复使用。
