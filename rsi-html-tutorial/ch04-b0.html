第二部 · 五级阶梯

第 4 章 · B0：只改这次答案

B0 是对照级，不是 RSI。它很有用：能把当前作文改顺、把当前代码改到过测试。但它故意不留下任何会改变「下一道题怎么做」的系统状态。

这一章只要记住

判据只有一句：输出变了，系统没变。任务一结束，批评、草稿、失败记忆全部扔掉。下一题，它还是原来那个它。

先看一个会混淆的场面

一个写代码智能体用人类提供的测试套件，最多试五次。每次失败它都改代码。看起来很「自我改进」。只要这些修复和反馈锁在当前任务里、不改变它处理后续任务的方式，它仍在 B0。

写作智能体按人类提供的评分表改作文，也不留下这次经验给以后写作，同样是 B0。

人规定评价规则和修改程序，AI 只在这些约束里改进当前输出。

三种经典实现，都停在会话里

下面三个系统被后来几乎所有智能体当零件用。把它们的实现看清楚，你才知道 L1 多出来的那一步是什么。

Self-Refine：生成 → 反馈 → 再写

Madaan 等人，2023 · arXiv:2303.17651 · 同一模型既当作者又当评论员

它想解决什么

人改文章靠「写完再读一遍」。模型通常一次生成就交卷。Self-Refine 把「再读一遍」写成固定循环，而且不训练、不外接评测器，只靠同一套权重的三次角色切换。

实现怎么走

  1. 生成：模型按任务提示写出初稿 y0。
  2. 反馈：把任务说明和 y0 塞进另一套提示，要求按维度（事实、语气、格式……）列出具体缺点，得到自然语言反馈 fb。注意：这里没有外部标准答案。
  3. 精炼：把 y0 + fb 再喂回去，要求「根据反馈改，不要丢失已经对的部分」，得到 y1。
  4. 重复 2–3，直到步数用完或模型自己说「不用再改」。

代码层面就是三次不同的 prompt 模板调用同一个 generate()。没有参数更新，没有把 fb 写入跨任务记忆。

技术难点

同一模型既出题又判题，会共享知识盲区。反馈往往又长又泛（「可以更清晰」），精炼步骤不一定知道改哪一句。若初稿已经对，再改有可能改错——这不是假想，后面 Self-Correction Bench 和 Huang 等人 2024 的研究专门量过。

留下什么
无。会话结束即丢。
人还控什么
反馈提示怎么写、循环几轮、什么叫停。

Reflexion：把失败写成一段话，塞进下一次尝试

Shinn 等人，2023 · arXiv:2303.11366 · 语言强化学习的雏形

它想解决什么

普通强化学习用数字奖励改权重，贵而且慢。Reflexion 用「一段自我总结」当瞬时记忆，让下一次尝试避开这次坑。它明确说这是上下文里的强化学习，不是改参数。

实现怎么走

  1. Actor（行动者）按当前提示和环境观察产出动作或代码。
  2. 环境或启发式评测器给出稀疏信号：过了测试 / 没过、任务成功 / 失败。
  3. Self-reflection 模型把轨迹和信号写成一段自然语言：「我在第 3 步用错了 API，下次应先读文档。」
  4. 这段话追加进一个情节记忆缓冲区（就是提示词里的一个列表），下一次尝试时一起读。
  5. 任务成功或尝试次数用尽后，缓冲区清空（或至少不进入下一个独立任务）。

和 Self-Refine 的差别：Reflexion 依赖外部环境信号（测试、执行错误），不只靠模型自己找茬；记忆是「给下一次尝试看的」，仍锁在同一任务的几次重试里。

技术难点

缓冲区一长，真正有用的那句会被淹没。反思可能归因错误（环境卡顿被写成「算法错了」）。没有外部信号时，它退化成 Self-Refine。论文里编程任务之所以有效，是因为单元测试提供了相对干净的对错。

留下什么
仅当前任务的几次重试。独立下一题默认不带。
人还控什么
记忆格式、何时写反思、重试上限、环境接口。

Tree of Thoughts：在「想法」上做搜索

Yao 等人，2023 · arXiv:2305.10601 · 推理树，不是学习算法

它想解决什么

从左到右一次写完，等于走一条路。有的题需要先试几条思路再选。ToT 把中间想法当成树的节点，用 BFS/DFS 或带启发的搜索在想法空间里走。

实现怎么走

  1. 定义「想法」的粒度：一步方程、一个谜题局部状态、一段计划。
  2. 生成器：从当前节点采样若干候选后续想法。
  3. 状态评估器：让模型给每个局部状态打分（或投票），剪掉差的枝。
  4. 搜索算法按分数扩展节点，直到得出答案或预算用尽。

实现上通常是：一个生成 prompt、一个打分 prompt、外面套一个普通的树搜索循环。没有跨任务的树被保存下来。

技术难点

想法粒度难定：太细变成逐 token 搜索，太粗又搜不到。评估器本身会错，错的启发式会让搜索在错误枝上浪费预算。计算成本随宽度指数上升。它提高的是这一题的搜索质量，不是系统以后如何搜。

留下什么
无。搜索树随题目丢弃。
人还控什么
想法定义、宽度、深度、打分提示、停止规则。

B0 的四条硬限制

综述归纳了四条。它们解释了为什么「再多迭代几次」解决不了自我改进。

  1. 经验不跨任务积累。中间结果、批评、纠正停在临时上下文。APEX-EM 指出：即便刚解过同一题，许多 LLM 智能体也必须从头再推一遍，因为没有持久的程序性记忆。
  2. 改进程序仍由人定义。AI 可以生成、核对、修改输出，但「这个过程怎么运转」仍是人写的。编码智能体修了没过测试的代码，并不持久改进以后的测试程序。
  3. 自生成反馈可能强化错误。同一模型生成和评价，会共享盲区。Self-Correction Bench 把「找到第一个错误推理步」视为瓶颈。没有可靠外部反馈时，修正甚至能把正确答案改错（Huang 等人 2024）。
  4. 固定评测下，多迭代收益有限。没有新信息，改答案可能几乎没好处。独立采样或外部验证有时更有效。固定验收器也会漏检：反复改代码去过一套不完整的测试，测试分涨了，没测到的失败还在。

调工具、做模拟，也不会自动把 B0 变成 L1

智能体可以调用搜索、解释器、机器人。只要这些互动的产物不写成跨任务状态，环仍然围着当前输出转。升级系统改进机制的责任还在人身上。

从 B0 跨到 L1，只多一件事

把 Self-Refine 的反馈存成「以后遇到同类题先读的规则」，并且真的在下一题检索出来——这就跨过了持久性门槛。至于规则怎么写、要不要验收，那是 L1 的问题。

其余 B0 与邻居工作（Self-Refine、Reflexion、ToT、ExpeL、持续学习、AutoML、ADAS）的逐步实现见 深挖 B0。
