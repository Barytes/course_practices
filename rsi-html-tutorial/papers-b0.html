B0：会话内精炼，什么都不留下

主线第 4 章已经把 Self-Refine、Reflexion、Tree of Thoughts 走了一遍。这里补上综述引用的其余 B0 与「看起来像学习、其实没有跨任务状态」的工作，并写清实现。

Self-Refine

B0 Madaan 等人 2023 · arXiv:2303.17651

它想解决什么

让同一模型在不训练的情况下，靠「写完再评、再改」提高当前输出质量。

实现怎么走

  1. 用任务提示生成初稿 y0。
  2. 换一套反馈提示，按事实/语气/格式等维度列出具体缺点。
  3. 把 y0 和反馈一起送回，要求只改被指出的问题。
  4. 重复直到步数用尽或模型自称完成。

三次角色共用同一套权重和 generate()。没有参数更新，没有把反馈写入跨任务存储。官方实现本质是 prompt 模板循环。

技术难点

同一模型既当作者又当评委，会共享盲区。反馈常空泛。初稿已对时再改可能改错。Huang 等人 2024 专门量化过「修正把对的改错」。

改了 / 留下什么
无持久状态。
人还控什么
反馈提示、循环轮数、停止规则。

Reflexion

B0 Shinn 等人 2023 · arXiv:2303.11366

它想解决什么

用自然语言反思代替数字奖励，让同任务的下一次尝试避开这次坑。作者称为上下文里的强化学习。

实现怎么走

  1. Actor 产出动作或代码。
  2. 环境或启发式给出稀疏成功/失败。
  3. 反思模型把轨迹写成一段话。
  4. 追加进当前任务的情节缓冲区，供下一次尝试读取。
  5. 任务结束后缓冲区默认丢弃。

依赖外部信号（单元测试、执行错误），因此在编程任务上比纯 Self-Refine 稳。记忆仍锁在同一任务的几次重试。

技术难点

缓冲区一长，有用句被淹没。归因错误会把环境故障写成算法错误。没有外部信号时退化成自说自话。

改了 / 留下什么
仅当前任务重试记忆。
人还控什么
记忆格式、重试上限、环境接口。

Tree of Thoughts

B0 Yao 等人 2023 · arXiv:2305.10601

它想解决什么

把中间「想法」当成树节点做 BFS/DFS，提高这一题的搜索质量，而不是改变以后如何搜。

实现怎么走

  1. 定义想法粒度（一步方程、局部谜题状态）。
  2. 从当前节点采样若干后续想法。
  3. 用另一个提示给局部状态打分或投票并剪枝。
  4. 按搜索算法扩展直到答案或预算用尽。

实现是生成 prompt + 打分 prompt + 普通树搜索循环。搜索树随题目丢弃。

技术难点

粒度难定；评估器会错；成本随宽度指数上升。它不留下「更好的搜索策略」。

改了 / 留下什么
无。
人还控什么
想法定义、宽度深度、打分提示。

APEX-EM

B0 对照 / 记忆提案 Banerjee 等人 2026 · arXiv:2603.29093

它想解决什么

指出 LLM 智能体普遍缺少持久程序性记忆：刚解过同一题，下一回合仍从头推。提案用结构化的程序–情节经验回放做非参数在线学习。

实现怎么走

  1. 把成功轨迹拆成程序性步骤和情节片段。
  2. 新任务时按结构检索，而不是只做向量相似。
  3. 在线把新经验写入回放缓冲，不改底座权重。

这是在批评 B0 的缺陷之后给出的记忆方案。若记忆跨独立任务留下并被以后检索，它开始踏进 L1/L4；综述在 B0 节引用它，是为了证明「没有持久程序记忆时，迭代再多也不积累」。

技术难点

结构化检索的模式一旦设计错，会系统性取回错误程序。缓冲增长后的索引和遗忘策略必须另做，否则退回 Reflexion 式淹没。

改了 / 留下什么
程序–情节记忆（若真正跨任务启用）。
人还控什么
记忆模式、检索规则、是否允许改权重。

ExpeL：智能体也可以从经验里抽「教训」

B0 对照 / L1 记忆苗头 Zhao 等人 2024 · AAAI · 论文

它想解决什么

普通 ReAct 智能体把轨迹留在当前提示里，下一题就忘。ExpeL（Experiential Learning）想在不改权重的情况下，把多道训练题的成败蒸馏成可复用的自然语言 insight。综述在 B0 节引用它，是为了点出「经验若不停在参数、记忆或操作规则里，就会下一题重犯」；ExpeL 自己其实已经在尝试把教训写成跨任务列表。

实现怎么走

  1. 在一组训练任务上跑智能体，把整段轨迹按成功/失败存进经验池。
  2. 另一次 LLM 调用对比成功轨迹和失败轨迹，写出几条短教训（例如「先检查库存再合成」）。
  3. 测试新任务时，把 insight 列表塞进系统提示，再按 ReAct 行动。
  4. 可选：测试过程中继续追加 insight。全程不微调底座模型。

实现上就是「轨迹日志 + 一次提炼提示 + 测试时拼接」。没有向量库时，insight 列表会越来越长；有的后续工作改成检索。它跨过了「下一题看不见」这道门，但仍由人规定怎么提炼、什么时候读。

技术难点

提炼模型可能写出漂亮但错的教训。训练任务和测试任务太像时，看起来很强，换分布就塌。insight 没有独立验收，错教训会污染以后所有题。列表一长，真正有用的那句会被淹没——这正是后面 ACE、HDSO、库漂移论文要解决的。

改了 / 留下什么
跨任务的 insight 列表（文本记忆，不是权重）。
人还控什么
训练任务集、提炼提示、测试时是否允许再写。

没有外部反馈时，自我纠正可能改错

B0 分析 Huang 等人 2024

它想解决什么

检验「让模型自己改自己」是否真能提高正确率。发现在缺少可靠外部信号时，修正会把正确答案改成错误答案。

实现怎么走

  1. 在标准推理基准上跑生成–纠正循环。
  2. 分开统计：错→对、对→错、对→对、错→错。

实现通常仍是 Self-Refine 式提示。关键测量是转移矩阵，而不是最终准确率。

技术难点

如果纠正提示泄漏了标准答案或用了更强评委，结论会翻转。综述用它警告 B0 的第三条限制。

改了 / 留下什么
无。
人还控什么
是否提供外部验证。

Self-Correction Bench / 定位第一处错误

B0 评测 Tsui 2026；Tyen 等人 2024 · Tyen: 相关工作

它想解决什么

把自我纠正的瓶颈定位到「验证」，尤其是找到推理链里第一个错误步。

实现怎么走

  1. 构造带逐步对错标注的推理链。
  2. 要求模型指出第一处错误，而不是只给最终对错。
  3. 比较「会做题」和「会查错」两种能力。

评测实现的难点是逐步标注昂贵，且错误边界有时有歧义（计算错还是抄题错）。

技术难点

若只看最终答案，会把「蒙对」和「真会改」混在一起。

改了 / 留下什么
无（评测集）。
人还控什么
标注协议、错误定义。

分解自我纠正：准确率–纠正悖论

B0 分析 Li 2026 · arXiv:2601.00828

它想解决什么

表明没有新信息时，反复改同一答案可能几乎不再涨分。

实现怎么走

  1. 固定评测器，增加修订轮数。
  2. 画准确率–轮数曲线，观察平台。

无。
人还控什么
轮数预算、是否允许新工具/新检索。

独立采样有时强过自我修正

B0 对照 Olausson 等人 2024

它想解决什么

在代码生成上比较「生成–执行–修复」和「多样本再选」。有的设置里，多采样加测试筛选不弱于复杂自我调试。

实现怎么走

  1. 同一模型生成 n 个候选。
  2. 用单元测试过滤。
  3. 与多轮自我调试比通过率。

提醒 B0 环的收益上限：固定验收器下，搜索宽度可能比深度修订更值。

技术难点

测试套件不完整时，两种方法都会过拟合测试。

改了 / 留下什么
无。
人还控什么
n、测试套件。

持续学习：会跨任务学，但通常不改学习法

持续学习让模型在一连串任务上获得知识并少忘旧的。学习目标、更新规则、经验日程、验收测试通常仍由人固定。只有当经验也能改「以后如何提出、评价或巩固适应」时，才靠近 RSI。

持续学习综述（预训练到对齐）

持续学习 Shi 等人 2025

它想解决什么

把大模型持续学习覆盖到持续预训练、指令微调、对齐、回放、参数高效更新、基于记忆的适应。

实现怎么走

  1. 按更新对象（全参、LoRA、记忆）和防遗忘技术（回放、正则、隔离参数）分类。
  2. 强调目标与更新规则通常保持固定。

这是综述用来定位「邻居」的地图，不是一个可运行系统。

技术难点

持续学习文献里「自适应」有时只指学习率，不指改学习议程，读的时候要对齐本教程的 L3 定义。

改了 / 留下什么
权重或记忆（在被综述的方法里）。
人还控什么
任务顺序、防遗忘目标。

持续学习方法梳理

持续学习 Wu 等人 2024

它想解决什么

补充持续学习在指令与对齐阶段的实践，说明回放和参数高效更新如何限制旧能力丢失。

实现怎么走

  1. 回放缓冲存旧任务样本。
  2. 新任务上联合旧样本微调。
  3. 或把新知识写进隔离模块。

环闭合在「新权重」，但「何时回放、回放多少」通常是超参，不是被改进的对象。

技术难点

回放比例一错，不是忘旧就是学不动新。缓冲隐私和存储也是部署难点。

改了 / 留下什么
模型参数 / 回放缓冲。
人还控什么
任务序列、回放策略。

AutoML 与智能体式 AutoML

AutoML 自动选模型、超参、流水线。搜索空间、目标、预算、评测器一般事先给定。当「用来搜索或评价改进的程序」变成可被后轮改进的持久状态，才碰到 RSI 边界。

ADAS / Meta Agent Search

L2 Hu, Lu, Clune · ICLR 2025（预印本 2024） · arXiv:2408.08435 · GitHub

它想解决什么

让元智能体在代码里发明新智能体。智能体 = Python forward(任务)→回答。

实现怎么走

  1. 给元智能体基本查询函数（约 100 行框架）。
  2. 档案可初始化 CoT、Self-Refine。
  3. 元智能体写新想法并实现 forward，两次反思检查新颖性。
  4. 验证集评价，出错最多修 5 次。
  5. 代码+指标入档案。每个域有自包含 search.py。

搜索空间图灵完备，因此能发明新积木，也能写出死循环或读验证标签的捷径。元算法本身不变，故不是 L5。主线第 6 章有对照讲解。

技术难点

评价贵导致迭代少；档案质量决定以后想象力；必须沙箱。

改了 / 留下什么
候选智能体代码档案。
人还控什么
基准、评价函数、元框架、迭代次数。

AFlow

L2 Zhang 等人 2025 · arXiv:2410.10762

它想解决什么

把智能体工作流编码成可执行图，用蒙特卡洛树搜索做代码级修改。

实现怎么走

  1. 节点是 LLM 调用或工具，边是数据流。
  2. MCTS 选择要改的节点/边，生成代码补丁。
  3. 执行工作流得到任务分，回传更新树统计。
  4. 留下高分图给推理时使用。

比纯提示搜索表达力强：一次修订能改整题期间的推理–工具交互。评价器固定，所以仍是 L2。

技术难点

图一复杂，搜索分支爆炸。执行失败与逻辑失败要分开，否则 MCTS 会避开一切「会抛异常但有潜力」的图。

改了 / 留下什么
工作流图代码。
人还控什么
评价器、MCTS 超参、允许的节点类型。

AgentSquare

L2 Shang 等人 2025

它想解决什么

把智能体设计拆成可复用模块，用进化和重组搜索。一种配置里发现的结构成为另一种的积木。

实现怎么走

  1. 定义模块接口（规划、工具、记忆……）。
  2. 突变或交叉模块组合。
  3. 在固定基准上评分，成功模块进入积木库。

模块化降低了 ADAS 那种任意 Python 的风险，也限制了发明全新积木的空间——空间由人定的模块类型决定。

技术难点

接口定错会导致「重组」只是换皮。模块在新基准上可能不组合。

改了 / 留下什么
模块库 + 组合方案。
人还控什么
模块类型、基准。

MLE-bench

评测 · 智能体 ML Chan 等人 2025 · ICLR

它想解决什么

评价机器学习工程智能体：在类似 Kaggle 的任务上做数据处理、建模、提交。

实现怎么走

  1. 提供数据集、提交格式和评分。
  2. 智能体在时限内迭代实验。
  3. 看最终分数和过程合法性。

它测的是智能体做 ML 工程的能力，默认 harness 在一场内可改训练代码，但不要求跨场留下改进器。综述用它说明智能体 AI 的评测场景。

技术难点

泄漏、手工规则绕过、以及把人类小时和 GPU 小时混比，都会扭曲排行。

改了 / 留下什么
当场的训练代码（通常不跨任务强制继承）。
人还控什么
题目、时限、评分规则。

PaperBench

评测 Starace 等人 2025

它想解决什么

评价智能体复现论文级研究工作的能力：读论文、写代码、跑实验。

实现怎么走

  1. 给定论文和部分资源。
  2. 智能体尝试复现声称。
  3. 按可复现性和部分分评分。

和 MLE-bench 一起，说明「会做研究任务」≠「会改做研究的程序」。

技术难点

部分论文实验不可复现是原论文问题，不是智能体问题，评分要拆开。

改了 / 留下什么
当场制品。
人还控什么
论文集合、评分量规。

AI Scientist-v2

智能体研究 · L2 相邻 Yamada 等人 2025

它想解决什么

迭代做研究工作流：选题、实验、写稿。把智能体能力扩到持续研究，而不是单次问答。

实现怎么走

  1. 模板化实验循环。
  2. 根据实验结果改下一实验。
  3. 生成论文草稿。

搜索空间、目标和评测仍大量事先给定。综述把它放在 AutoML/智能体邻居：自动化研究工作 ≠ 改进器被后轮修改。

技术难点

实验声称需要独立验证，否则自我写稿会放大幻觉。这正是 ARA / rit 协议后来想补的基础设施。

改了 / 留下什么
实验代码与草稿（当场）。
人还控什么
研究主题范围、评价。

理论祖先

Gödel Machine

理论祖先 Schmidhuber 2003 · arXiv:cs/0309048

它想解决什么

一台可以改自己代码的问题求解器，但只有在能证明「这次自修改的期望效用净增加」时才执行修改。

实现怎么走

  1. 系统包含求解器和一个证明搜索器。
  2. 证明搜索器寻找关于自修改的形式证明。
  3. 一旦找到证明，执行修改，新代码包含新的证明搜索器。

这是「有效 RSI」的理论极限版：不允许没有证明的自修改。实践中，对大多数有趣改动无法证明净有益，所以 DGM、STOP、Gödel Agent 都改成经验验收。

技术难点

证明义务太强导致几乎不能改；弱化后又失去安全保证。整个现代 RSI 工程都在这两极之间找门禁。

改了 / 留下什么
整个自修改代码（理论）。
人还控什么
效用的形式化、证明系统。
