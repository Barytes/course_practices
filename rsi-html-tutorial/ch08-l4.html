第二部 · 五级阶梯

第 8 章 · L4：上线以后继续改自己

L3 关心下一课学什么。L4 关心：真实任务里的互动，怎样改记忆、技能或执行部件，并且这些改动会塑造以后的行为和以后能收到的反馈。

这一章只要记住

环是：观察部署互动 → 提出持久适应 → 修订智能体部件 → 验收并留下 → 在以后任务里复用 → 收集新反馈再重复。目标、权限、受保护评测、重大发布权仍在人这边。

三种机制，对应三种「留下什么」

综述按轨迹蒸馏、迭代改智能体系统、有选择地录取与上线来组织。它们差在改什么、何时被再用、如何证明继续有用。

机制一：轨迹蒸馏成可复用制品

原始轨迹又长又贵。蒸馏后的制品更短、更好查、更容易在以后任务里调用。制品形态从「一段话」走到「可执行代码」。

文本经验记忆

  • Dynamic Cheatsheet：冻结模型，跨相关题目维护一份不断演化的笔记（策略、代码片段、已知坑）。同一模型既答题也策展：加入提炼出的教训，删掉过时条目。没有单独的留出验收门。
  • ACE（Agentic Context Engineering）：短条目 +「有帮助/有害」计数器，只打补丁不整篇重写，避免压缩丢信息。
  • ReasoningBank：面向多步智能体，失败和成功都蒸馏成带标题的短策略，下一题先检索。由评委先给轨迹贴标签再抽取。

难点：没有外部真值时，模型会把偶发成功写成普遍规则。笔记变长后检索变差。这是「留下去」的最小实现，也是最容易留下错教训的实现。

结构化记忆

APEX 把策略地图建成「里程碑 + 前置关系」图。每回合结果沿路径回传，另一步加上还没试过的有前途分支。规划时在「已知好路」和「没试过的路」之间选。PersonaAgent / PAHF 按用户组织记忆；MemToolAgent 存储失败工具调用的批评，并调整每次检索条数。

结构让「何时可复用」可检查，但图的边一旦标错，以后会系统性避开本来该试的路，或反复走一条错路。

程序性技能库

Trace2Skill：冻结智能体在域任务上滚出轨迹；错误分析师和成功分析师分别提案，再分阶段合并成可移植技能目录，后来的智能体当作说明书一次载入。PRACTICE 面向具身：可训练的技能学习器做批量增删改合；先从专家轨迹学基本生成和库维护，再用不同执行器在同一任务上的成/败对照学「失败意识」，最后在自己的编辑分布上向更强老师蒸馏。

在线获取的代表是 PANDO：网页智能体在部署中从每次 rollout 蒸馏「防止重复失败的规则」和「替代多步浏览器子目标的参数化例程」，带置信度的录取和降级。PILOT 则让监督器从一次长地平线直播中蒸馏程序和失败模式，使以后的会话带着积累的技能开始。

Metis：文本计划够用了，再编译成可调用工具

Dai 等人，2026 · 双记忆：文本 + 代码

实现怎么走

  1. 文本库存计划、环境事实、坑；代码库存可调用工具。
  2. 反射器维护文本条目。
  3. 一条文本计划被多次复用后，重写成可调用工具。
  4. 只在沙箱里编译并跑对，才录取进代码库。
  5. 检索同时覆盖文本条目和工具描述。

这是 L4 很典型的「门禁」：先当话留下，证明反复有用，再升级成代码。Evo-Harness 把目标从单个工具扩到整个 harness，把失败或负向评价的任务写成跨任务模式和任务特定程序。SHAPER 在具身里同时进化文本规划指导和一个沙箱 Python 函数（负责挑选给规划器看的上下文）。

技术难点

「频繁复用」不等于「正确」。错误计划被 Repeated 使用，会更快变成错误工具。沙箱编译只保证语法和依赖，不保证工具在分布外仍对。评测要同时看任务质量、执行成本和构造成本，不能只看分数。

机制二：迭代改智能体系统本身

这里改的不是「记得什么」，而是技能、量规、harness 或底下的权重。关键问题：哪些部件可以变，哪些录取标准在它们变的时候保持固定。

共演化的循环问题

如果判官和答题人一起变，分数变高可能只是判官变松。DecoEvo 的做法：

  • 在文本空间里同时进化「解题技能」和「量规生成技能」；
  • 目标解耦，优化时不给金标准量规；
  • 解题技能靠条目级量规反馈更新；
  • 量规生成器过两道与总分无关的审计：结构审计（是否覆盖任务要求）、对比审计（能否区分接近的回答），再做帕累托验证；
  • 生成器看不到解题人的总分，因此不能靠「把量规变容易」来抬自己。

这是 L4 里对「评测被污染」最认真的工程之一。它仍不是 L5：量规生成技能在变，但「用什么审计来换量规」这套元规则是人写死的。

基准：模型到底能不能改自己的架子

  • HarnessDev：从最小种子和少量开发案例建完整 harness，按下游反馈迭代。候选冻结后在隐藏任务上评成功率和执行器 token 成本；创建者和执行器分开，以便在固定执行器下比较 harness。
  • ASPIRE：只给一个含糊目标，数据、更新方法、验证信号都交给智能体，权重和 harness 都可以动；分数门控，验证分不涨就回滚。
  • S3Gym：扣掉验收器结果，逼智能体自己判断轨迹，比较原始历史、压缩摘要、参数训练三条路。

Lin 等人的分析把两件事拆开：做出有用的持久更新，和解题时用得上这些更新。更新能力与底座模型能力几乎独立——小模型做的更新，收益可以接近前沿模型。从更新后的 harness 获利的能力则非单调，失败集中在两模式：相关制品没被激活，或激活了但不忠实执行。实践含义：能力投资应放在解题智能体，而不是进化器。

机制三：录取、维护、上线

提出改动之后，谁能成为持久状态？控制点有三：录取前、使用中、发布进操作系统。

  • HDSO：策展模型看紧凑执行轨迹，提出带明确验证计划的假说。同一批任务跑两次：当前批准库当对照，加上候选技能当处理。只有两次运行的差异支持假说才录取。分阶段加大样本，最后在独立任务上确认。防止从噪声轨迹里蒸馏出捷径或执行器根本不听的规则。
  • 库漂移：无界堆积会在任务分还没掉之前就让检索变差、进步停滞。对策是追加式证据日志（技能对结果的贡献）、贡献衰减则退役、限制活跃技能数量、在「元技能」指导下写新技能。退役太狠比完全不管更差。
  • 技能编辑过滤：另一项分析发现，仔细过滤技能编辑，比根据任务结果反复重写技能，更能涨分。
  • Tax AI：生产报税系统里，从业者纠正写成字段级证据，反复失败聚成评测目标。编码智能体查轨迹、评测和仓库，实现修复，过针对性和回归评测。只能改产品的有界部分（抽取模式、源选择、税务引擎映射、评分器）。架构和产品设计仍归工程师。每个修复以 PR 进人审，解决不了的退回从业者。人是最终录取者，审查引入的延迟是环的运行成本。

怎么评价 L4

特征风险叫持久更新失败：一条被接受的改动可能在弱点暴露前影响许多后续决定。失败机制包括：从噪声证据推出错教训；把对的教训用到有效范围外；该调用时没调用；保住新行为却牺牲旧能力。最终任务分无法分开这些机制。

可信评价必须把每条留下的改动连到：产生它的证据、后来怎么被用、对新题和旧题的影响。当前证据多半是有界任务流、有限的模型/任务/环境组合；反馈还可能有噪声、评测器随系统一起变、有用制品仍可能不影响执行。

Finding：L4 把自治从「选经验」转到「决定经验的哪些后果在部署中持久存在」。人握住目标、受保护录取标准、访问边界、以及对重大发布的最终权。

Cheatsheet、ACE、Metis、HDSO、库漂移、Tax AI 等见 深挖 L4。

最后一级：当「改进过程」自己变成瓶颈——搜索总走老路、开发分不再预测外部分——就要改改进器、评测器或研究政策，并让后继者继承。
