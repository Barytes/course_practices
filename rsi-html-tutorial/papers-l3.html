自适应出题与自博弈

Absolute Zero Reasoner

L3 Zhao 等人 2025 · arXiv:2505.03335

它想解决什么

零外部题目：同一模型既出题又答题，用 Python 执行器验证题合法和解正确，用可学性奖励让课程跟着 Solver 走。

实现怎么走

  1. Proposer 按演绎/溯因/归纳三种类型，参考缓冲区出题。
  2. 执行器过滤非法程序。
  3. Monte Carlo 估计 Solver 成功率 r̄；可学性奖励在全对/全错时为 0，中间难度为 1-r̄。
  4. Solver 得二元对错奖励。
  5. TRR++ 联合更新两角色。

主线第 7 章逐步手讲。这是学习者条件经验的干净实现。

技术难点

可学性≠未来涨分；课程可能变窄；执行器只保证相对该形式题的对错。

改了 / 留下什么
权重 + 题目缓冲。
人还控什么
题型、执行器、奖励公式、优化器。

Search Self-Play (SSP)

L3 Lu 等人 2026a

它想解决什么

搜索智能体里，出题人奖励依赖当前解题人表现，搜索题课程随 Solver 变而变，不必人每批重写。

实现怎么走

  1. Proposer 生成搜索题。
  2. Solver 去搜。
  3. 用 Solver 表现构造 Proposer 奖励。
  4. 两边更新。

把「信号→题分布」连起来。奖励设计仍是人写的。

技术难点

搜索环境若可被利用，双方会共谋出无信息量的题。

改了 / 留下什么
出题与解题政策。
人还控什么
奖励设计、训练程序。

R-Zero

L3 Huang 等人 2026a · 相关

它想解决什么

Challenger–Solver，无需外部答案标签。Challenger 的不确定性奖励来自当前 Solver 多次回答是否一致。

实现怎么走

  1. Challenger 出题。
  2. Solver 多样本作答。
  3. 一致性/分歧构造不确定性奖励。
  4. 伪标签方案训练 Solver。

一致性是模型感知难度的代理，不是正确性。综述特意警告这一点。

技术难点

模型可能在含糊题上稳定地一致地错。伪标签会固化错误。

改了 / 留下什么
两角色权重。
人还控什么
不确定性奖励、伪标签、优化。

STP 自博弈定理证明

L3 Dong and Ma 2025 · ICML

它想解决什么

联合训练猜想器和证明器。当前证明器勉强能证的猜想拿去训练猜想器；已检查证明训练证明器。

实现怎么走

  1. 猜想器生成命题。
  2. 证明器尝试证明。
  3. 证明助手（Lean 等）检查。
  4. 按「靠近前沿」的难度选猜想做训练。

形式域提供可靠正确性；学习者依赖的选择准则负责「有用难度」。两条不要混。

技术难点

猜想可能语法合法但数学无聊。证明奖励稀疏，需要课程。助手只能检查形式化后的命题。

改了 / 留下什么
猜想器+证明器权重。
人还控什么
形式域、证明检查、训练规则。

Propose, Solve, Verify

L3 Wilf 等人 2026

它想解决什么

验证代码生成：解题人导出的难度标签伴随例子去提示新规格；规格要能编译，解要被形式检查才进训练。

实现怎么走

  1. 根据 Solver 表现给题打易/中/难。
  2. 条件生成新规格。
  3. 编译检查。
  4. 解相对规格形式验证。
  5. 通过的才训练。

论文报告三种目标难度的实现难度大量重叠——难度条件出题只有部分课程控制力。

技术难点

规格可能形式正确但任务无用。形式验证不保证规格表达了用户意图。

改了 / 留下什么
编码模型 + 规格集。
人还控什么
验证器、难度方案、训练配方。

VisPlay

L3 He 等人 2026a

它想解决什么

视觉语言推理：图像条件提问者 + 推理者。提问者奖励靠近规定中点的多数票置信度，外加多样性惩罚。

实现怎么走

  1. 给定图像，Questioner 提问。
  2. Reasoner 多样本作答。
  3. 中间置信度得不确定性奖励。
  4. 多样性惩罚抑制重复问法。

Reasoner 变，其一致性就改变未来提问奖励。信号可扩展，也可能反映含糊。

技术难点

图像源固定则视觉多样性有上限。中点奖励会偏好模棱两可的视觉问题。

改了 / 留下什么
VLM 权重。
人还控什么
图像源、奖励、优化。

环境里自主练习

Voyager

L3 Wang 等人 2023 · arXiv:2305.16291 · GitHub

它想解决什么

Minecraft 终身学习：自动课程 + 可执行 JS 技能库 + 迭代提示（环境反馈、异常、自我验证）。不微调 GPT-4。

实现怎么走

  1. 课程 LLM 根据物品栏、历史、技能提出稍难目标。
  2. 向量库检索 top-k 技能。
  3. 生成 Mineflayer JS 并执行。
  4. 失败则把错误写回再改。
  5. 成功后用描述嵌入入库（Chroma + skills.json）。

主线第 7 章逐步对照源码结构。新世界可加载旧技能库。

技术难点

自我验证撒谎；技能只增不删导致检索退化；课程提示是人写的。

改了 / 留下什么
技能库 + 探索历史。
人还控什么
游戏接口、课程提示、技能表示。

SIMA 2 / ASKA

L3（完整设置） team 等人 2025（DeepMind SIMA 团队）

它想解决什么

固定任务实验只说明自我生成轨迹有用，不说明任务选择自治。完整 ASKA 里 Gemini 任务设定器根据奖励模型评估把练习对准弱技能。

实现怎么走

  1. 评测当前各技能。
  2. 任务设定器针对弱项出练习。
  3. 采集轨迹训练智能体。
  4. 再评，更新弱项列表。

自治属于含任务设定器的耦合系统，不要求行动模型亲自做每个课程决定。

技术难点

奖励模型不准会练错技能。固定任务论文数字不能当成 L3 证据。

改了 / 留下什么
政策 + 课程状态。
人还控什么
任务设定器、奖励量规、训练程序。

SEAgent

L3 Sun 等人 2026c

它想解决什么

陌生软件上的计算机使用智能体：世界状态模型判断轨迹并描述 GUI 变化；课程生成器更新持久软件指南并据此生成以后任务。

实现怎么走

  1. Actor 操作 GUI。
  2. World State Model 评估轨迹。
  3. Curriculum Generator 写/改软件指南。
  4. 用指南生成新任务。
  5. Actor 再学。

指南把早期探索带进以后练习，帮助超出已探索操作。

技术难点

错误指南条目会长期带偏。GUI 变化描述不准导致任务无解或太易。

改了 / 留下什么
软件指南 + Actor。
人还控什么
软件接口、评估模型、学习程序。
