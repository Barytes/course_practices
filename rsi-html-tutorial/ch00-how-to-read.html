这份教程怎么推进

综述很长，引用超过两百项。如果一上来按论文顺序读，很容易在名词里迷路。我们改成「先建立一张地图，再把每座建筑拆开」：

  1. 第 1–3 章：为什么要 RSI，尺子怎么量，环由哪九个零件组成。
  2. 第 4–9 章：从 B0 走到 L5。每一级都先讲人话，再选 2～4 个代表系统把实现走一遍。
  3. 第 10–13 章：同一套环放到科学、机器人、软件、医疗里，看反馈贵不贵、能不能复现。
  4. 第 14–15 章：工业现场怎么接这条环，以及八个还没打通的缺口。
  5. 第五部：综述引用的每一项工作单独成卡：它想解决什么、代码/权重/数据怎么改、难点在哪、人还握着什么。

因此请按章节顺序读主线。第五部可以当词典随时翻，但不要用它代替第 3 章——没有「改进环」这张图，那些卡片会变成互不相关的项目介绍。

生活比喻

像学做饭。第 3 章是「火、锅、菜、计时器分别是什么」；第 5 章是「按菜谱炒」；第 9 章才是「改菜谱怎么写」。不要指望封面那句「人类造的最后一代 AI」等于已经有人把灶台全自动化了。

你需要准备什么

  • 不需要会训练大模型，也不需要会微积分。
  • 需要能接受三件事：程序可以改另一段程序；模型权重是一堆可学习数字；一次评测分数不等于「变聪明了」。
  • 会一点 Python 更好，因为后面会用超短伪代码说明 STOP、Voyager、AZR 在干什么。看不懂代码也可以只读旁边的人话。
  • 遇到具体论文想核对原文时，卡片里会给出 arXiv 或官方链接。

必须先会的三问：环、遗产、权限

综述把「改进环」当作分析单位，而不是把「用了进化算法」或「用了强化学习」当作分类标准。后面每一章都建立在下面三问上。

1. 环在哪闭合？

闭合的意思是：这一轮的结果，会成为下一轮的起点。如果模型改了一段代码，评测完就扔掉，下一题从空白重来，环没有闭合。如果改完的提示词、技能、权重、研究策略被存下来，下一轮接着用，环才闭合。

卡住时先念：这次改动，下一题还能看见吗？看不见，就还在 B0。

2. 留下了什么？

留下的东西叫系统状态。它可能是：

  • 模型参数（权重）
  • 一段提示词或角色设定
  • 技能库、记忆、工具代码
  • 智能体的脚手架（harness：提示、工具循环、校验逻辑）
  • 出题器、评测器、研究政策

同一种技术可以落在不同级别。关键不是「它改了提示词」，而是「谁决定改哪一句、改完是否进入下一轮、下一轮会不会再改改法」。

3. 人还控哪一步？

自治不是「AI 做的步骤变多了」，而是「哪一类决定从人手里交出去了」。人仍然可以规定目标、预算、安全红线、最终能不能上线。综述认为这些外部约束并不自动取消 RSI，但必须说清楚，否则会把「在人设计的考场里刷分」说成「AI 在自己改进自己」。

每一级只多交出一种决定

级别AI 新接管的决定人通常仍握住的
B0只改当前答案一切长期状态、一切流程
L1按已写好的步骤执行，结果可留下目标、步骤、验收标准
L2根据失败证据选择下一次改法目标、任务边界、验收标准
L3根据自己目前会什么，决定下一课学什么总目标、学习规则、评测器
L4根据真实上线反馈，决定哪些经验变成长期规则权限、发布权、受保护评测
L5改改进器、评测器或研究政策，并让后继者继承总任务、安全边界、资源权限

更高级别不自动等于更好。L5 系统也可能改坏自己、钻评测空子、或把错误写进后继者。综述把「自治范围」和「改进质量」分开评。

第五部怎么用

主线章节会挑代表系统细讲，避免一章里塞进五十个项目。第五部则按综述引用清单，把每一项工作补全为同一张卡片：

  • 它想解决什么：用一句人话。
  • 实现怎么走：数据从哪来、改哪一块、怎么验收。
  • 技术难点：真实系统里最容易翻车的地方。
  • 改了什么 / 人还控什么：用来对齐 B0–L5。

卡片页顶部有搜索框，可按系统名、作者或技术词过滤。也可以先打开 217 篇参考文献总表，按作者跳进对应卡片。

关于「查看了每一项引用」

教程依据综述正文、参考文献、附录工业表，以及各工作的论文、仓库或官方说明来展开实现。一部分 2026 年工业博客没有公开训练代码，我们会写清「公开了什么、没公开什么」，而不是假装看到了内部集群上的每一行脚本。

符号很少，遇到就念出来

综述里有三个公式，第 2 章会用手算讲。现在只需知道：

  • HCI：把不同考场的分数拉到同一把 0–100 的尺子上。0 是该考场第一年的前列水平，100 是满分。
  • 改进环：经验 → 提出修改 → 验收 → 留下 → 下一轮。
  • 结构 L5 / 有效 L5：前者证明「改过的改进器确实被下一轮拿去用了」；后者还要证明「在差不多的预算下，它能造出更强的后继者」。
