Theseus（正文案例）

L2–L3 现场 环境–数据–模型共演化 · 见第 14 章

它想解决什么

前提：环境让知识可访问、动作可验证；任务执行产生学习证据；更强模型扩大能探索的问题。每一轮应给后续轮贡献可复用能力。

实现怎么走

  1. 把 refinement 经验变成环境 refinement 任务，训练环境模型。
  2. 智能体在重建环境里找真正难点，生成针对性训练数据。
  3. 这些数据训练任务模型。
  4. 更强模型支持下一轮环境和任务生成。

干净工作区通过率 +21.7–51.6 个百分点；带 Collection Map + Event Log 的重建环境量规 +18.65–39.67 个百分点。这是共演化的第一步，不是完整环已经转起来。

产品线在表中对应 Argus、SetupX。

技术难点

必须把「桌子收拾干净」和「人变聪明」分开量。范围蔓延说明环境变丰富也会诱导过度动作。

改了 / 留下什么
环境制品、验证模块、任务数据。
人还控什么
共演化日程、量规、完整学习周期是否启动。

Lark / 飞书（正文案例）

L1–L2 数据环 企业数据底座 · 第 14 章

它想解决什么

智能体要改进自己，先要有不断演化的数据基底。企业里文档、消息、会议持续产生新信息。

实现怎么走

  1. 构造企业知识图谱（实体、事件、人、时间），并检查授权。
  2. 绝对判断丢掉明显不可用输出，再用 GSB 比较决定是否晋升。
  3. 失败归因到时间不一致、查询被扭曲、源质量差等，映射到具体改进。
  4. 人定义标准、审关键样本、批重要变更。

相对 RAG 基线，人评可用性 52%→65%，自动评 47%→56%。自动评委与人约 84% 一致，分歧多半因为自动评委更严。

技术难点

图谱错误会直接传进答案。时间敏感问题必须按查询时过滤，避免用到未来信息。

改了 / 留下什么
图谱、评价标准、归因后的数据。
人还控什么
标准、关键样本、重要变更。

Humanlaya（正文案例）

有界 L4 / 外环 L5 苗头 交付驱动的数据质检 RSI · 第 14 章

它想解决什么

生产单元是复杂多文件任务包。内环修当前批次，外环改质检系统自己。

实现怎么走

  1. Quality Checker → Refiner → Delivery Checker 修当前包。
  2. 交付后汇总审查、客户反馈、下游使用。
  3. 对质检系统提出带版本的修改，在未参与产生该修改的包上评价，加人审再晋升。

V0→V4：关键缺陷包 9.0%→3.7%，人工 48→27 分钟。扫描 PDF 案例：把抽取失败误当成文档质量差，于是新规则进入下一版本。

技术难点

外环改的是质检器，已经碰到「改进机制」；人仍握最终批准。留出评价必须真的没参与产生该修改。

改了 / 留下什么
带版本的质检指令、技能、few-shot。
人还控什么
人审与最终发布。

ModelBest / Forge 工程（正文案例）

L2 工程搜索 工业 AI 工程自动化 · 第 14 章

它想解决什么

实现训练框架、优化内核、配并行，执行反馈相对客观，可能比开放式研究更早自治。

实现怎么走

  1. 人和 AI 维护含规格、评价、经验的知识库。
  2. 智能体建立高层架构后进入 AutoResearch：实现、测正确性与性能、修瓶颈。
  3. 成功内核并入主路径；经验写回知识库给下一项目。

ForgeTrain：约 8 小时匹配 Megatron-LM v0.15；MiniCPM4 MFU 有公开公司数字。ForgeStencil 把方法扩到科学计算内核。

技术难点

对比的「工程师月」是估算。知识库质量决定搜索空间。这是公司报告，不是独立复现的 L5。

改了 / 留下什么
训练框架 / 内核代码 + 知识库。
人还控什么
规格、评价、架构约束。

腾讯混元 Hyra（正文案例）

L2；评测器 refinement 碰到 L5 问题 经验驱动搜索 · 第 14 章

它想解决什么

不把人手工作流写死，而给宽解空间，用实验证据指导下一次搜索。Experience Bank 存代码、日志、分数、评测器反馈。

实现怎么走

  1. Context Agent 重组灵感上下文。
  2. 多个 Proposal Agent 在隔离沙箱里构造新解。
  3. 结果写回银行。
  4. 若评测器不完整或被利用，可用积累经验修订评价机制再继续搜。

nanochat 验证 BPB 0.9015 vs 0.9109；nanoGPT Speedrun 76.4s vs 77.5s；SOL-ExecBench 0.771 vs 0.754。

技术难点

公开材料没有 RQGM 那么明确的独立锚。修订评测器后旧分如何作废、如何重评，是你要追问的。

改了 / 留下什么
经验银行 + 可能被修订的评测机制。
人还控什么
停止规则、预算、评测器治理是否独立。

Agent-Native Research Lab / ARA（正文案例）

研究基础设施 可验证研究文物 · 第 14 章

它想解决什么

后继智能体需要失败实验、中间证据、可执行规格，而不是只给人看的论文。

实现怎么走

  1. ARA 同时保留科学逻辑、代码、探索图、原始证据。
  2. rit 协议把声称锚到执行轨迹，从日志重新抽取结果。
  3. 分析声称可用 Lean 4 等检查。只有过门的声称进入共享研究状态。

对先前工作问答 93.7% vs 论文 72.4%；RE-Bench 复现 57.4%→64.4%。硅设计实例用工业 EDA 做可综合验证。

技术难点

形式验证不能证明规格表达了人真正想要的能力。保密数据下只能部分重放。

改了 / 留下什么
可继承研究文物。
人还控什么
验证门、哪些声称可以进共享状态。
