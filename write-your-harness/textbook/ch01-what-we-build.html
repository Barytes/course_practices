第 1 章 · 我们要造什么

先把整张图摊开。后面每一章只负责图上的一个方框。读完你应当能指着图说：模型从哪进、工具从哪出、上下文在哪变长。

这一章只要记住

Agent = 模型 + 上下文 + 工具 + 循环。少任何一块都不是我们要造的东西：没有工具只是聊天；没有循环只是一次函数调用；没有上下文，模型会失忆；没有模型，你只是在写普通脚本。

先看一次完整的「修 bug」

用户说：「add(2, 3) 应该等于 5。」工作区里有一个文件 calc.py，现在写的是 return a - b。一次成功的 agent 跑起来，消息列表会这样长：

第 3、5 行是模型在点名；第 4、6 行是 harness 在干活并汇报。磁盘上的 calc.py 变了，是因为第 5 行的工具真的执行了，不是因为模型「心里想改」。

生活比喻

还是修自行车。第 3 行是「把车翻过来我看看」；第 4 行是你把看到的告诉他；第 5 行是「把这颗螺丝换成那颗」；第 6 行是「换好了」；第 7 行是「可以骑了」。如果你换好了螺丝却不说话，他下一秒还会再要同一颗螺丝。

四块零件，少一块会怎样

零件它负责拿掉之后
模型看上下文，决定下一句人话或下一个工具你只能手写 if/else，那是普通程序
上下文把已经发生的事摆在模型眼前它每次都像第一次见面，会重复劳动或乱改
工具真的读、写、跑命令它只能空谈「应该改哪一行」
循环反复「问 → 做 → 记」直到停止它只能动一次手，修不完多步骤的 bug

一张流水线

虚线是闭环：工具结果必须写回 messages，模型下一轮才能看见。没写回去，等于没发生。

图上的 complete() 就是「把当前整份上下文交给模型，拿回一条助手消息」。教学里我们用假模型（预先写好它会说什么）；接上真 API 时，这个函数变成一次网络请求。循环的形状不变。

一条消息里有哪些格子

整台机器的状态就是一个 Python 列表。每一项是一个 Message 盒子。打开 miniharness/types.py，字段只有这些：

字段人话例子
role这句是谁说的system / user / assistant / tool
content这句话的正文"改完了。" 或工具输出的文本
tool_calls助手还想让你干什么（可空）[read calc.py]
tool_call_id这条观察对应哪一次点名call_1。只有 role=tool 才用
name观察来自哪个工具read

ToolCall 更小，只有三格：id（这次点名的编号）、name（工具名）、args（参数字典）。

所以 Message.role 只有四种你需要关心的。上游仓库可能再拆出通知、失败尝试、会话事件。那是它们的扩展，不是循环的必要条件。

不变的，和会过时的

印在书里还算负责印在书里就是在骗你
循环的形状某框架今天的类名
工具结果必须回传「必须用某某编排库」
评测要用瘦架子某年某榜第一名的提示词
高风险动作需要硬约束某家沙箱的具体系统调用表
上下文会按轮数变贵某模型「刚好 200K 就够」
扩展点应该挂在循环旁边某插件 API 今天的字段名

写到哪里

文件miniharness/types.py
符号Message、ToolCall、user()、system()、tool_result()
怎么跑打开文件，把四个 role 和上面那张表对一遍。本章没有新测试。

代码怎么对上原理

  • user("hello") 就是造一条 role=user 的盒子，省得每次手写字段。
  • tool_result(call, "ok") 会自动带上 tool_call_id，这样模型知道「ok」是对哪一次 edit 的回复。
  • to_dict() 把盒子变成普通字典，方便存 JSON。第 7 章存轨迹会用到。

先别管

「模型即 Agent」这种口号的意思是：模型越来越会自己决定调什么工具，编排层显得没那么重要。它和「Harness 更重要」并不打架——模型越自主，出错的影响面越大，越需要约束、记录、压缩、权限。保障层的价值在涨，类名编排的价值在跌。第 6、12 章会回到这里。

自测

  • 如果工具成功改了文件，但忘了把 ok 写进 messages，下一轮模型会怎样？
  • 上面那份 7 行轨迹里，循环一共问了模型几次？
  • 为什么 tool 消息需要 tool_call_id，而 user 消息通常不需要？
自测答案
  1. 模型看不见改动，可能再改一次，或认为失败。磁盘状态 ≠ 模型状态。
  2. 三次：第 3、5、7 行都是 assistant，各来自一次 complete()。第 4、6 行是工具，不问模型。
  3. 一轮里可能同时点名好几个工具，回来的观察必须对得上是哪一次。用户说话没有「对应哪次点名」这个问题。
