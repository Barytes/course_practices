写自己的
Harness

一本把循环写进手指、把读仓库写成习惯的 Agent 工程教材。每章先讲人话，再拿手算例子，最后才对代码。深度放在「先别管」里，第一遍跳过也不影响动手。

这本书在干什么

读完你应当能自己写出一个 coding agent 的 harness，并且知道：哪些部分十年内大概不会变，哪些部分三个月后就会被一次 release 改掉。后者请去 GitHub，不要来翻这本已经印死的目录。

先承认一件事

用书籍研究 AI 和 Agent，发布即过时。去年扎堆的 LangChain 教程基本死光了；任何「开源两个月的大而全电子书」也一样。这本书不跟它们比页数。它只做两件书还做得来的事：把循环写进你的手指，把读仓库的方法写进你的习惯。

六个对照仓库

真要学 Agent 开发，直接看这些。nanocode 和 mini-swe-agent 几乎冻结，适合当骨架；其余四个更新很快，适合当时间线。

怎么开始

浏览器打开本页即可阅读。代码在上一级目录的 miniharness/。先读第 0 章、术语表和动手地图，然后按章往包里对照。不需要 API key：python -m miniharness demo 用脚本模型就能修一个假 bug。手机阅读：barytes.github.io/course_practices/harness。

两遍读法

第一遍（把机器跑起来）第二遍（把取舍看懂）
看什么每章开头黑底框、超小例子、「写到哪里」「先别管」、对照仓库的问题清单、自测
做什么跑 python tests/test_miniharness.py 和 python -m miniharness demo默写 run_agent，按第 14 章补一个缺口
跳过什么Effect、Cordis、Seatbelt 配置、PTC 包名不要跳过「观察必须写回」和「评分器在循环外」

第四部出现陌生词，打开术语表。第十到第十三章会把手伸进每个仓库：先手算走完一轮请求，再看历史上改了取舍的 PR。不要在第 11 章停下来学一门新的 TypeScript 库——那会把「读取舍」变成「背框架」。

和那些仓库的关系

教材里的文字是重新写过的教学文本，miniharness/ 是一份独立的教学实现，不是任何上游的拷贝。上游各自有许可证（多数 MIT / Apache-2.0），阅读源码时请看仓库里的 LICENSE。

第四部给出的版本号会过时。过时之后不要改教材凑新数字——运行 python -m miniharness watch 把 releases 拉回来，让 AI 帮你梳理时间线，有疑问再点进具体 commit 和 issue。那才是正餐。
