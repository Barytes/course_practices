第二部 · 零件

第 7 章 · 接上 CLI 与轨迹

循环若不能从终端喊出来，它就还是库。轨迹若不能存成 JSON，评测和复盘都无从谈起。这一章把「能跑」和「能回放」补上。

这一章只要记住

CLI 只做三件事：选工作区、选模型（脚本或在线）、把 messages / events 打出来或存下来。漂亮的终端界面是皮肤，不是循环的入场券。

先跑一次，看见整台机器

demo 做的事情可以念出来：

  1. 把 labs/broken_calc 整棵复制到临时目录（源树里的 bug 原封不动）。
  2. 用剧本模型按「读 issue → 读源码 → 改那一行 → 跑测试 → 停」走完循环。
  3. 循环外面再跑一遍单元测试当裁判。
  4. 在终端打印对话摘要，最后一行是 PASS 或 FAIL。

你应该看到 PASS。这就是最小的「能跑的 agent 产品」：输入任务，输出轨迹和是否做完。

生活比喻

前六章是发动机和刹车。本章是钥匙和行车记录仪。没有钥匙，发动机只能在实验室转；没有记录仪，出了事故说不清刚才发生了什么。

四条命令各自干什么

命令人话要不要联网
demo用自带剧本修 add()，证明整机连通不要
eval换夹具或换剧本，专跑评测不要（除非你自己塞在线模型）
run "…"对某个工作区跑一次任务给 --script 就不要；否则要 API key
watch拉六个仓库的 GitHub releases要。第 15 章再用

第二条没有 --script 时，会走 OpenAICompatModel：还是那个 complete() 插座，只是里面变成一次 HTTP 请求。循环文件一个字都不用改。

轨迹比聊天记录值钱

run --save out.json 会写出两个数组：

两份名单不要混：

  • messages 是模型的世界。少写一条，它就当这件事没发生。
  • events 是工程师的世界。记录「这一拍开始了 / 工具跑完了」，不必寄给模型。第 11 章的可观测性从这里长出来。

mini-swe-agent 把轨迹叫 trajectory，并在每一步的收尾处保存——崩溃也不丢。deepseek-harness 把 session log 当成唯一事实来源。pi 更进一步：应用侧的消息和寄给模型的消息不是同一份名单。miniharness 现在把两份几乎做成同一份，是教学简化。

不要等有了数据库再开始存。一份 JSON 已经够用来重放、做第 9 章的评测、喂给另一个模型问「它刚才在干什么」。

代码怎么对上原理

  • cmd_demo 内部调用 run_eval，所以它测的是「循环 + 工具 + 评分器」，不是只测打印。
  • _print_messages 跳过 system 提示，只把人话和工具预览打到终端。这是皮肤：删掉它，循环照样正确。
  • OpenAICompatModel.complete 把 Message 翻译成 OpenAI 的 JSON 信封。翻译层属于模型适配器，不属于 loop.py。

TUI 可以很晚再做

nanocode 用颜色在普通终端打印。pi-tui 走「写在普通滚动缓冲里、只重绘脏行」，系统自带的搜索和选中还在。Codex 的 TUI 是全屏画布。opencode 还有桌面和 IDE。这些都是同一根循环上的皮肤。

先别管

差分渲染、全屏抢终端、浏览器多标签——选哪一种，问的是「用户还把终端当日志看吗」，不是「哪种更先进」。先把 CLI 和 JSON 打出来。

可选：换成真模型

设置 OPENAI_API_KEY（以及可选的 OPENAI_BASE_URL、MODEL），然后：

python -m miniharness run "修 add()" --workspace /tmp/copy-of-broken-calc

真模型会胡来。先在副本上跑，并记住：我们的 bash 没有操作系统沙箱。

常见卡住

  • 系统里没有叫 python 的命令。——用课程的 venv，或写 python3。评分器内部已经用 sys.executable，不依赖 PATH 上的名字。
  • demo 把教材自带的 labs/broken_calc/calc.py 改好了。——不该发生：它先复制到临时目录。若你手动改了源树，测试会失去失败用例。
  • 想做交互式多轮聊天。——run 现在是一次性。外层再套一个 input() 循环即可，那是 nanocode 的外层，不是内层循环。

自测

  • 为什么 demo 要复制到临时目录再改文件？
  • events 和 messages 各给谁看？
  • 把打印函数全部删掉，循环还正确吗？轨迹还在吗？
自测答案
  1. 避免把教材自带的 bug 仓库改「好」之后，下一轮学生或测试没有失败用例了。
  2. messages 主要给模型（和人类复盘对话）；events 给开发者看循环有没有按预期跳转。
  3. 循环正确。只要 --save 还在写 JSON，轨迹就在。打印只是皮肤。
