生活比喻

学生说「我做完了」不算分。老师拿同一张卷子在旁边再做一遍。隔离副本则是：每位学生发一份新卷，不能在别人写过的卷子上改。

为什么必须 copytree

  1. 源树保持有 bug，下一轮学生、下一轮 CI 还有失败用例。
  2. 两次评测互不污染。上次修好的 calc.py 不会让这次「没干活也 PASS」。
  3. 真 SWE-bench 对每个实例也是一个干净容器 / 干净工作副本。我们用临时目录模拟这件事。

代码怎么对上原理

  • run_eval 里评分命令用 sys.executable -m unittest …，避免 macOS 上没有名为 python 的命令。
  • 剧本里的 bash 命令同样要用当前解释器。否则循环里的「测试通过了」和循环外的评分器可能一个绿一个红。
  • EvalResult.trajectory 是 messages 的字典版，方便 demo 重新打印。

把剧本换成真模型，评分器不用改

这就是第 3 章「模型只是插座」的回报。run_eval(fixture, model) 的第二个参数可以是 ScriptedModel，也可以是 OpenAICompatModel。评分器根本不看模型是谁。

脚本模型证明的是 harness：循环、工具、隔离、评分这条管子是通的。真模型证明的才是智力。管子不通时先修管子，不要先骂模型。

先别管

真 SWE-bench 还有 Docker 镜像、失败测试列表、补丁提交格式。那是评测基础设施，不是循环。你会跑基准测试时去 clone mini-swe-agent，不要把那套抄进教学包。

你可以立刻加的三道题

  • 再做一个夹具：测试本身是错的，看 agent 会不会「修测试」骗分。
  • 把 bash 关掉（allow_bash=False），只留 edit。脚本在循环里不能跑测试，但评分器在循环外——仍然可以 PASS。
  • 故意让脚本重复 read 四次，确认 stop_reason 变成 repeat_loop，并且这次算 FAIL 还是「没修完」。

常见卡住

  • edit 的 old 少写了注释 # BUG: should add。——文件里是整行，少一个字符就命中 0 次。
  • 在源树而不是副本上手工改好了 calc.py。——EvalTests 会变成「没干活也绿」，这是夹具被污染，不是 harness 变强。

自测

  • 为什么评分器在循环外面跑，而不是相信模型调用 bash 的输出？
  • 隔离副本和 mini-swe「每次动作独立子进程」解决的是同一类问题吗？
  • 模型改了 test_calc.py 让断言永远为真。循环外的评分器会怎样？
自测答案
  1. 模型可以谎报测试通过，或只跑了子集。评分器由 harness 以已知命令执行。
  2. 一类：都在消灭隐式状态。副本消灭「上次评测留下的修复」；独立子进程消灭「shell 里悄悄 export 的变量」。
  3. 现在会 PASS——这是玩具评测的漏洞。真基准测试会保护测试文件，或在干净环境用官方测试重跑。第 14 章请你补上「拒绝写 test_*.py」。
