第二部 · 零件

第 6 章 · 护栏：先能停下来

循环默认会一直转。模型一旦卡住——同样的 grep、同样的失败测试——账单和磁盘都会遭殃。这一章先装三道便宜的刹车，再说明它们不是沙箱。

这一章只要记住

护栏回答三个问题：还能走几步？是不是在原地转圈？这条路径还在工作区里吗？前两道在 guards.py，第三道在 tools.py 的 Workspace。它们都是 Python 检查，不是操作系统沙箱。挡得住糊涂，挡不住换一种写法的 bash。

没有护栏的循环会怎样

剧本里每一次 grep 都返回「找不到」。没有步数上限的循环会：问模型 → grep → 再问 → 再 grep……直到你手动杀进程，或信用卡报警。

生活比喻

帮手找不到 14 号扳手，于是一遍一遍喊「递我 14 号」。你没有「最多喊十次就停」的规矩，就会在车棚里站到天黑。护栏不是教他修车，是允许你下班。

三道刹车

1. 步数预算

一步 = 一次 complete()。默认比如 20。到点之后，循环不再问模型，而是追加一条助手说明「step limit reached」然后结束，stop_reason 记为 step_limit。

为什么按 complete 计，不按工具计？因为一次 complete 可能带三个工具。预算要卡的是「模型还能想几次」，那才是贵的部分。

2. 重复指纹

把「工具名 + 参数」做成一串短指纹。例如 grep::{"pat": "add("}。若连续 N 次指纹相同，视为卡死。

这很笨：模型可能在用同一条 grep 搜不同仓库——但 miniharness 的工作区只有一个根。笨是优点：规则能讲清楚，测试能写死。

3. 路径关在工作区里

这道闸写在 Workspace.resolve，不在 guards.py。read / write / edit / glob / grep 的路径一旦解析到根目录外面，工具返回 error: path escapes workspace。循环把它当普通观察写回去，模型可以改主意。

bash 仍然是缺口：命令在工作区里启动，但 curl 和 rm -rf / 不走路径解析。miniharness 故意不假装有一份命令黑名单——那种检查用字符串包含就能绕过，写进教材当「安全」是在骗人。真要拦危险命令，看第 12 章的操作系统沙箱。

你可以自己加一道字符串拒绝列表当练习；加完请立刻试：把 rm -rf / 改成 rm -rf "$HOME"，名单还挡得住吗？挡不住，你就理解「护栏 ≠ 沙箱」了。

写到哪里

文件miniharness/guards.py
符号Guards.before_step、before_tool、GuardError
怎么跑python tests/test_miniharness.py GuardUnitTests

代码怎么对上原理

  • before_step 在 complete 之前调用。超了就抛 GuardError。
  • before_tool 在 tools.run 之前。连续相同指纹就抛 GuardError。
  • loop.py 抓住 GuardError，把它变成一条 assistant 人话并设置 stop_reason。循环的正常形状仍然只有一个 while True。

护栏不是沙箱，也不是审批

谁在检查挡住什么挡不住什么

本章护栏你的 Python步数爆掉、同一工具连打三次换参数继续空转；bash 里的任意命令
审批（第 12 章）人点头高风险动作先问你你点了同意之后的一切

四层可以叠。教学顺序必须是：先能停（本章）→ 再让人点头、让 OS 动手（Codex）。很多人一上来就想「做沙箱」，结果循环还在空转烧钱。

先别管 · 指纹可以更聪明

生产系统会看「同一文件同一行反复 edit 失败」「测试命令输出哈希不变」等。pi 和 opencode 把这类策略做成可替换的钩子。miniharness 只做连续相同 tool+args，是为了让测试一眼能看懂。

自测

  • 步数到上限时，应不应该再执行已经点名但还没跑的工具？
  • 为什么要把 GuardError 写成观察/助手说明，而不是让程序 traceback？
  • 连续三次 read path=a.py 会停。连续三次 read 不同文件呢？
自测答案
  1. 看你把检查放在哪。miniharness 的步数卡在下一次 complete 前，本轮已点名的工具仍会跑完。这是一种合理取舍：不浪费已经付费的那次思考。
  2. traceback 是给程序员看的。模型需要看见「因为什么停了」，人类回放轨迹时也需要。评测还要把 stop_reason 记下来。
  3. 不同路径指纹不同，不会触发。若你认为「狂读也是问题」，要另加「每任务最多 read 次数」。
