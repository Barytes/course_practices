开始

第 0 章 · 这本书为什么不是一本书

先约定三件事：我们在造什么、哪些知识印在纸上还有用、你每章要动手做什么。后面每一章都按这个分界写。

这一章只要记住

模型会说话，也会「请你帮我做一件事」。你的程序真的去做，把结果告诉它，再问下一步——这件事叫循环。框架名字、插件协议、某家 SDK 的类名，三个月后就会换。用书籍练习循环仍然划算；用书籍背类名，性价比不如直接问现在的模型。

三个词先钉死

打开这本书之前，不要求你写过 Agent，也不要求你训练过模型。要求你会一点 Python：函数、dict、for 循环。下面三个词全书都会用，现在用人话钉死。

模型你把字发给它
它把字发回来
工具读文件、改文件、
跑命令——真干活
循环它说「请干活」
你干完再问它

模型在本书里几乎总是别人的云端接口：你发一段文字和一份「我能帮你做哪些事」的清单，它回一段文字，有时附带「请执行 read，路径是 calc.py」。它不会自己打开你的硬盘。

工具是你的 Python 函数。模型只能点名，不能越权。点了 read，是你的函数去 open() 文件。

循环把这两边接起来。没有循环，你只是在聊天；有循环，它才能连续读文件、改一行、跑测试。

生活比喻

请一个帮手修自行车。他看不见车棚里的工具，只能开口：「把 14 号扳手递我。」你递扳手，告诉他结果，他再决定下一步。Harness（本书要写的那层程序）就是递扳手、记账、到点喊停的人。模型是那个会修车但没有手的人。

这套「会说话的人 + 替他伸手的人 + 反复问」合在一起，就是本书说的 Agent。单次问答的聊天窗口还不是。

为什么「Agent 电子书」会集体死亡

2024 到 2025 年，市面上堆满某一家编排库的教程。它们教你记一串当时流行的类名。模型变了，工具协议变了，那些类名先死，书还躺在网盘里。这不是那家库「坏」，是把会过时的实现细节当成了学科内容。

2026 年又一批「工程实践全书」开源。开源两个月，在模型和 harness 都按周发版的速度下，目录本身就是一份过期地图。它也许能喂饱电子书收藏爱好者；真想做 Agent 应用或写 harness，那种组织方式甚至不如打开一个还在提交的仓库，或者直接问现在的模型。

再打一个比方

像拿 2019 年的「共享单车创业宝典」学出行。车还在，公司已经换了三茬。你要学的是「两个轮子 + 锁 + 计费」，不是某家 App 的活动页怎么配。

这本书故意只做两件事

  1. 把不变量写进手指。你对照一份不到一千行的 miniharness：循环、六种常用工具、上下文截断、循环检测、玩具评测。做完就能复现一个模块，也能从空白文件写出自己的 harness。
  2. 把「会过时的部分」改成阅读方法。pi / opencode / codex / deepseek-harness 更新很快。第十到第十三章会把每个仓到快照日为止、改了架构的历史 PR（以及哪几条最重要）写成目录。我们不把它们的 API 抄进教材当标准答案，而是告诉你：releases 里找破坏性变更，commit 里找取舍，issue 里找他们后悔什么。

nanocode 和 mini-swe-agent 几乎冻结，所以第二、第八章会带你把源码当标本看。其余四个，教材写架构 + 改了取舍的历史 PR + 那一票意味着什么，版本号全部打上快照日期。不会把几千条已合并 PR 逐条印成 changelog 镜像——那正是这本书反对的事。第四部出现看不懂的词，先打开术语表，再往下读。

六个仓库各解决什么问题

现在不需要打开它们。只要知道：卡住时该去谁家。

你卡住的问题先看谁人话不要指望它给你什么
循环到底长什么样？nanocode250 行把骨架摊开沙箱、压缩、插件、评测
怎样公平地比较模型？mini-swe-agent考试要用同一张卷子漂亮的 IDE、插件市场
最小但能每天用？pi车架小，配件自己挂把所有功能都做进核心
大规模产品怎么不崩？opencode很多人同时用，要能看见、能取消一份「读完就不会再改」的架构图
怎么在真机器上敢放手？codex操作系统来拦危险命令一份跨平台都完美的沙箱神话
怎么让能力可替换？deepseek-harness连循环都是插头稳定的公开 API（它自己写了会破）

每一章你要做什么

  1. 读懂这一步在整张图上的哪一格。每章开头黑底框是「只要记住」；看懂它再往下。
  2. 看一个超小例子：三轮对话、两个工具调用、两三个文件这种规模。能用纸笔复述，再看代码。
  3. 打开 miniharness/ 对应文件，对照「现在动手」和「代码怎么对上原理」。第一到第九章以写代码为主；第十到第十五章以读仓库为主。
  4. 跑测试：python tests/test_miniharness.py。不需要 GPU，不需要 API key。测试挂了，先看断言在说哪一个形状错了。
  5. 做自测。先自己说人话，再展开答案。

看到「先别管」怎么办

那是给以后挖仓库准备的深度，跳过不影响写 miniharness。第一遍以黑底框和超小例子为准。

代码写到哪

全部在 write-your-harness/miniharness/。不要每章新建互不相通的脚本。完整对照表见 动手地图。

你需要准备什么

  • Python 3.11+。核心只使用标准库，不用安装 PyTorch、LangChain 或任何 Agent 框架。
  • 会写函数、list / dict。看到 @dataclass 就把它想成「带字段名的盒子」：Message.role 是这个盒子上贴的标签。
  • 能打开 GitHub。第四部会给你具体文件路径，那些路径也可能搬家——搬家本身就是你要观察的信号。
  • 可选：OPENAI_API_KEY 和兼容端点，用来把脚本模型换成真模型。实验不依赖它。请先把 python -m miniharness demo 跑到出现 PASS。

常见卡住

  • 「那我还读这本干什么？」——读循环，读取舍表，读第 15 章的 releases 方法。别背类名。
  • 「我想要生产级。」——先写完 miniharness，再 clone 一个对口的仓库，按第 10～13 章的问题清单往下挖。
  • 「我想要最新最佳实践。」——运行 python -m miniharness watch，不要等下一版电子书。
  • 「JSON、API、token 这些词好晕。」——打开术语表。第 1 章会用超小对话再讲一遍。

自测

合上这一章前，确认你能用自己的话回答：

  • 聊天机器人和 Agent 差在哪一步？
  • 为什么去年某家编排库的教程会过时，而「调用模型直到它不再要工具」不太会过时？
  • 六个仓库里，哪两个适合当标本，哪四个适合当时间线？
  • 读完这本书，你应该能交什么？一份能跑的 harness，还是一份框架笔记？
自测答案（先自己想）
  1. 聊天是一问一答就结束。Agent 会在中间多次「请你干活」，把结果看完再继续，直到它不再要工具或被护栏按住。
  2. 类名和编排层绑定的是某一年的 SDK；循环绑定的是「模型会发出工具调用」这件事本身。只要工具调用还在，循环就在。
  3. 标本：nanocode、mini-swe-agent。时间线：pi、opencode、codex、deepseek-harness。
  4. 一份能跑的 harness，外加以后自己拉 releases 的习惯。不是框架笔记。
